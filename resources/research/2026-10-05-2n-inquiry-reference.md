# 2N 询盘页参考与峰徊适配记录

- 调研日期：2026-10-05
- 参考页面：[2N Request Wheel Quote](https://2nforged.com/contact-us/)
- 调研目的：为峰徊 `/request-a-quote` 的转化节奏、字段和兜底联系方式提供结构参考
- 使用边界：只记录页面结构与交互思路，不复制品牌、文案、联系方式、样式或业务承诺

## 1. 参考页当前结构

2N 当前 Contact 页面实际承担“轮毂报价询盘”职责，页面结构很短：

1. `Request Wheel Quote` 标题与低门槛说明；
2. `What to send` 准备清单；
3. 姓名、邮箱、WhatsApp、消息组成的短表单；
4. 邮箱与 WhatsApp 直接联系兜底。

准备清单主要围绕车型/VIN、轮毂尺寸、表面处理、数量、外观方向、品牌或保密要求，以及质量照片、视频或验厂沟通。页面明确告诉客户不必在第一次联系时备齐所有规格。

## 2. 借鉴项

- 询盘页本身就是主任务，不再用大 Hero 和二次 CTA 阻挡表单。
- 用“把已经知道的信息发来”降低首次联系门槛。
- 在表单附近给一份很短的准备清单，而不是先要求客户理解完整工程流程。
- 保留已确认邮箱等直接联系渠道，作为表单不可用时的兜底。
- 字段数量保持克制，未知技术项留到后续工程确认。

## 3. 不直接沿用

| 2N 现有做法 | 峰徊处理 |
|---|---|
| 全页只面向轮毂 | 先选择轮毂、三电铝制品、定制铝制品或自密封轮胎 |
| 车型/VIN 是通用准备项 | 只在轮毂上下文提示；其他产品线显示自己的输入清单 |
| 一块自由消息承载全部业务信息 | 分离客户类型、产品线、项目描述和产品上下文，便于分流与追踪 |
| WhatsApp 作为公开渠道 | 只有号码、责任人和响应流程确认后才公开；客户号码本身可作为可选回复方式 |
| 工厂访问、视频和质量资料直接承诺 | 依据项目主体、保密和资料批准状态逐案确认，不在通用表单承诺 |
| 表单提交后直接进入业务承诺 | 峰徊只在数据库事务成功后显示询盘号；邮件状态单独记录 |

## 4. 对现有实现的影响

当前 `src/components/inquiry-form.tsx` 仍是轮毂长表单：企业、车型、轮毂系列、数量等均被设为必填，不能服务四条产品线，也不符合个人客户无需公司信息的规则。`src/app/request-a-quote/page.tsx` 仍传入轮毂 `productFamilies`，并在表单前放置额外 Hero CTA。

当前 `src/content/request-a-quote.ts` 和 `src/content/contact.ts` 还包含“已安全记录”“确认邮件已发送”“销售团队会跟进”等表述。生产存储仍是进程内 Map，发信也未形成可验证的送达闭环，因此这些文字在真实持久化完成前不得上线。

详细施工要求见 [询盘页 Page SPEC](../../PAGE-SPECS/request-a-quote.md)。
