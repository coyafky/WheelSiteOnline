## 2. 路由机制

```
浏览器请求 /zh/products/wheels
        │
        ▼ src/proxy.ts
  localeFromPathname → "zh"
  NextResponse.rewrite("/products/wheels")
  headers: x-fh-locale=zh, x-fh-public-path=/products/wheels
  cookies: fh-locale=zh
        │
        ▼ src/app/products/wheels/page.tsx（同一份代码）
  getLocale() 读 x-fh-locale
```

**关键设计**：一套 `app/` 目录 + 前缀 rewrite。**不存在 `src/app/[locale]/` 路由段**。

### 为什么这样设计

- 英文保持无前缀，**不破坏已收录 URL**（V3.0 明确警告的迁移风险）
- 避免 `[locale]` 段带来的所有子路由重排
- Next 16 的 Proxy 在请求早期改写，RSC 与静态资源都正确

### 铁律

**URL 决定语言**。cookie 与 `Accept-Language` **不会**把英文 URL 重定向到译文（`proxy.ts:27-28` 注释 + `e2e/publication-qualification.spec.ts:38-48` 验证）。

## 3. 翻译的三层

| 层 | 载体 | 位置 |
|---|---|---|
| UI 字典 | `dictionaries/{en,zh,es,th}.ts` | `src/lib/i18n/dictionaries/` |
| 正文 | WordPress Page / post 的按语言记录 | WP |
| 业务文案 | 各域 `*-copy.ts` | `src/lib/i18n/`（如 `flow-formed-copy.ts`） |

### UI 字典纪律

- 四个字典的**键集合必须一致**（`tests/i18n-routing.test.mts:20-25` 强制）
- 缺键时 `translateStrict` 返回**键名本身**（`types.ts:119-121`）→ 便于发现但会露给用户
- 【目标】缺键改为返回 `null` + 构建期校验，避免线上露键名

## 4. 发布资格门槛（四层一致）

同一份 `getPublicLocalesForPath(path)`（`publication.ts:35-69`）被四处消费：

| 消费点 | 位置 | 行为 |
|---|---|---|
| 页面渲染 | `layout.tsx:99-101` | `locale !== "en" && status !== "public"` → `notFound()` |
| metadata | `layout.tsx:60-85` | 只给公开语言出 canonical / hreflang |
| sitemap | `sitemap.ts:62-68` | 只纳入公开语言 |
| 语言切换器 | `language-switcher.tsx:77-81` | 未公开语言渲染为 `disabled` |

**当前实现**：除首页外一律 `return ["en"]`（`publication.ts:66-68`）

## 5. 已知缺陷与修复

### 缺陷 1：`localizedAlternates` 默认值使 hreflang 与发布门槛脱钩 ⚠️ High

```ts
// src/lib/i18n/types.ts:80-93
export function localizedAlternates(
  pathname: string,
  current: Locale,
  readyLocales: readonly Locale[] = INDEXABLE_LOCALES,   // ← 默认 ["en"]
)
```

**20 处调用，19 处没传第三参**（唯一传参的是 `src/app/page.tsx:31`）。

**后果**：一旦某路由对 `/zh` 开放（即 `getPublicLocalesForPath` 返回含 zh），该页面的 hreflang 仍会被默认值清空 → **页面可访问但 hreflang 为空**，搜索引擎看到的语言关系是错的。

**修复（P0）**：
1. 让 `readyLocales` 成为**必填参数**，删掉默认值
2. 所有调用点显式传 `await getPublicLocalesForPath(path)`
3. 加单测：对任意 path，`alternates` 的语言集合必须等于 `getPublicLocalesForPath` 返回值

### 缺陷 2：跨语言 entityId 缺失 ⚠️ High

- 首页靠 `key`（`pages.ts:26`）
- Insights 靠 post 内 `translations_json`
- 其余靠「英文 slug 直通」

**后果**：一旦某语言需要不同 slug，`localizedPath()` 立刻失效。

**修复（P1）**：`fh_translation_group` 提升为真正的 `entityId`，前端用它做 hreflang / 切换 / sitemap 聚合。

### 缺陷 3：未收录语言的 404 依赖未验证行为 ⚠️ Medium

`layout.tsx:99` 调 `notFound()`，e2e 断言页面含 `name="robots" content="noindex"`，但**仓库内无代码产出该 meta**。

**修复**：在 `not-found.tsx` 或 layout 显式设置 `robots: { index: false }`，并加 e2e 验证。

### 缺陷 4：缺译 UI 策略不统一 ⚠️ Low

同一 `/zh` 页面可能同时出现「键名」和「英文正文」。

**修复**：统一为「回退到英文 + 页内提示」，禁止露键名。

### 缺陷 5：cookie 语义偏差 ⚠️ Low

`proxy.ts:45-49` 每请求写 `fh-locale`，`index.ts:18-25` 当偏好读，但 header 永远被设置 → 属死逻辑。

**修复**：要么删掉 cookie 回退分支，要么明确用途并加校验。

## 6. 语言切换器

`src/components/language-switcher.tsx`
- `<select>` 组件（`:28`）
- 用 `localizedPath` + 保留 query + hash（`:50`）
- `window.location.assign` 全量跳转（`:56`）
- 未公开语言渲染为 `disabled` option（`:77-81`）
- 挂载在 `site-header.tsx:202`

【目标】切换时保留实体（用 `entityId` 而非路径拼接），避免跨语言落到 404。

## 7. 翻译内容工作流【目标】

```
① 中文/西语/泰语草稿在 WP 里创建（post_status=draft, fh_locale_status_json.xxx=draft）
② 人工/Agent 翻译 → 审核 → 把 fh_locale_status_json.xxx 改为 approved
③ publication.ts 的 getPublicLocalesForPath 返回含该语言
④ sitemap / hreflang / 切换器自动收录
```

**当前进度**：首页已完成（H01–H05 逐语言 Page）；其余页面族待迁移。

**默认拒绝原则**：新语言记录默认 `draft`，**不允许默认 approved**。
