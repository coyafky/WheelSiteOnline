## 四、⚠️ 更正我起草计划时的一处错误

计划 §2.3 与 §五-D4 写了「`5*112??`（2 条，问号是脏字符）」—— **这条是错的，不存在这个值**。

**错因**：我早先用一个「展开固定下标数组」的 SQL 给 PCD 计数，那个方法会让标签与数字错位（真值 `5*108` 被排到了 `5*112??` 的位置）。

**更正后的真实分布**（用 `JSON_TABLE` 逐行展开）：
```
5*114.3 294 | 5*112 136 | 4*100 127 | 5*108 70 | 5*120 45 | 6*139.7 39
5*112, 5*114.3 32 | 8*100, 8*114.3 32 | 5*100 25 | 5*113.1 14
10*100, 10*114.3 8 | 4*100, 4*114.3 6 | 4/5*100 3 | 4*114.3 2 | NULL 2 | 4*108 2 | 5*115 1 | 6*170 1
```
→ **PCD 侧零脏值**（含问号的记录不存在；`4/5*100` 与逗号并列都是前端本就能解析的合法写法）。

**仍然成立的脏值只有宽度**：`6.6`（1 条）、`8.25`（4 条）。

📌 **教训**：统计 JSON 数组里的值，**必须用 `JSON_TABLE(... COLUMNS(... PATH '$.字段'))` 逐行展开**，不能用「固定整型表 join + 路径里拼下标」——后者一旦行数不匹配就静默错位，且结果*看起来*完全合理。
