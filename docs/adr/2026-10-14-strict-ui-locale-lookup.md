# 界面词条按语言严格查找

- 日期：2026-10-14
- 状态：已采纳，逐步迁移中
- 范围：Next.js 本地 UI 字典，不包括 WordPress 正文的预览回退。

## 背景

站点已支持 `en`、`zh`、`es`、`th` 路由，字典键集合也有测试，但 `createT()`、`getTranslator()` 和 `translatorFor()` 会在目标语言缺词时静默显示英文。页面看似可用，漏译却无法从运行结果辨认。

## 决定

本地界面字典使用严格查找：先取当前 locale 的值；缺失时返回词条键，让测试、开发预览和渲染检查能够发现缺口。英文不再作为非英文 UI 的隐式回退。

需要预览未翻译的 WordPress 正文时，继续使用既有内容适配器和预览规则；不得把正文回退行为与 UI 字典混为一谈。页面正文、SEO、图片说明和产品展示名仍按各自的数据契约逐页迁移及审批。

## 后果

已覆盖的字典键必须在四种语言中都有文案。新增键由键集合测试保护。迁移中的模块如果调用了缺失键，会显示键名而不是英文，这可能在用户界面留下可见提示，因此每次迁移必须同步补齐四语字典并验收目标页面。全站正文未完成前，非英文索引仍受现有发布门槛控制。

语言标签、URL 前缀和 `Intl` 格式 locale 集中在 `src/lib/i18n/types.ts` 的 `LOCALE_CONFIG`；索引资格继续由独立的 `INDEXABLE_LOCALES` 审核白名单决定。页面专属长文案使用按页面命名的类型化 copy 模块，事实字段与翻译字段分开。旋压轮毂页是首个该类切片，四语翻译仍标记为草稿；WordPress 只有通过本地化 `locale_status` 的内容才会被页面适配器视为已批准，语言未批准时不得开放索引。
