# 全站暖白 Astryx 呈现架构

- 日期：2026-10-11
- 状态：实施中
- 来源：用户要求全站采用 Astryx Neutral，并明确偏好白色、暖色调；前端仍为 Next.js，内容后台仍为 WordPress。

## 背景

现有 Astryx 仅局部包裹表单、弹窗和少数反馈组件；站点主视觉仍以黑灰橙、深色页首为主。`DESIGN.md` 记录的是旧页面实测，不是这次迁移的目标。项目已有 WordPress 内容接缝、服务端轮毂目录和落库询盘，界面迁移不能改变这些事实的归属。

## 决定

1. 使用与 `@astryxdesign/core@0.6.7` 匹配的 Neutral 主题源码作为静态主题起点，映射为峰徊的暖白、暖灰、克制铜色。主题 CSS 在首屏加载，根布局声明浅色模式，Astryx Provider 只作为客户端边界承载服务端页面。
2. 全站公共界面使用统一主题令牌。可复用交互优先使用 Astryx；品牌 Hero、真实产品卡、工程规格、文章正文等继续由项目领域组件渲染并采用相同的颜色、字体、间距、圆角和焦点规范。
3. WordPress 已批准内容先经服务端适配器成为稳定 `src/content` 视图模型，再进入页面；任何 Astryx 组件不得读取 REST 原始字段。产品资格、同一真实 variant 筛选、询盘持久化与邮件状态保持现有服务端契约。
4. 已有验证表明当前 Astryx `CheckboxInput` 不能承载多值 GET 的业务 `value`，`Pagination` 不提供所需服务端链接；在有经验证替代方案前，保留原生控件与链接。静态 FAQ、文章全文和规格表也保留可索引、无 JavaScript 可读的原生结构。
5. 以共享外壳、询盘链、产品链、内容链推进；每批通过桌面/窄屏、键盘焦点、控制台、关键 URL 和表单回归，再扩展到下一批。

## 与历史决定的关系

DEC-082 的“局部 Theme”是旧阶段的回归保护措施；本决定将主题范围扩展到全站。DEC-084 的“只迁移重复交互基础设施”继续约束组件选择，但全站所有自有组件也要采用统一令牌。DEC-086、DEC-087、DEC-089、DEC-092 等业务与技术门槛不放宽。

## 后果

共享令牌和页首模式改变会影响多页面视觉，需要截图与交互回归。固定版本的主题源码需要保留生成来源与构建步骤，升级 Astryx 时逐项审查。WordPress schema、产品发布条件和询盘 API 无需因主题迁移改动。
