# 首页逐语言模块与发布合同

日期：2026-10-16。状态：已采纳，首页试点本地验收通过；全站迁移按批次评审。

## 背景

首页现有五个组件由路由固定编排；WordPress 一条 Page 内保存多语言 JSON。编辑人员不能按语言修订模块，缺译时前端可能显示英文正文，SEO 入口也未读逐页逐语言的批准状态。目标架构和迁移范围见 [`全站多语言模块架构重规划`](../../outputs/reports/2026-10-16-multilingual-module-architecture-proposal.md)。

## 决定

1. 首页以稳定页面键 `home` 关联独立语言 Page，旧聚合字段在迁移期只读保留。每个语言版本有独立正文、SEO、审批和撤回状态；不可凭 URL 前缀推断已发布。
2. 服务端把 WordPress 内容归一化并校验为类型化 `PageView`。React 组件只渲染受控模块。首页 H01–H05 全部必需；可移动模块可以交换顺序，但不能隐藏。
3. 页面与 metadata、sitemap、hreflang、语言切换共用逐语言公开资格。已批准译文缺失时该语言不公开索引；这是负责人于 2026-10-16 对此前“四语全部开放索引”指示的更新。
4. 迁移采用双读。新独立语言 Page 优先；旧聚合 Page 仅在该语言尚未迁移时作为兼容来源。新记录被撤回时必须阻断旧内容回退。前端中文、西语或泰语公开页面不得回退英文正文。
5. 本轮只完成首页试点。通过验收后由负责人评审全站迁移；其他页面不因首页实现而自动视为已接管。

## 2026-10-17 A-01 执行补充

全站逐路径资格先接入一个服务端判定点。首页按独立语言 Page 的正文、模块和 SEO 结果决定公开集合；负责人已确认 WordPress 暂时不可用时，英文首页的 `local-home-v1` 本地快照仍可公开索引。其他页面族在逐语言审核完成前只保留既有英文公开资格，不把四语路由注册或 UI 字典当作译文批准。未批准的语言路径直接访问返回 404，预览仍需授权且不进入公开集合。

语言 cookie 只记忆主动切换；无前缀 URL 始终表示英文，不按旧 cookie 或 `Accept-Language` 自动跳转。这样同一路径的页面、metadata、sitemap 与切换器可以使用同一公开语言集合，也避免旧偏好把访客送到草稿 URL。此项更新取代 `DEC-095` 中“完整页面按语言偏好自动跳转”的历史实现；其他页面族获得正式批准后仍需逐页补齐正文、SEO、媒体与责任人证据。

## 理由与边界

独立 Page 使用 WordPress 原生修订和权限能力；受控模块避免运营编辑器触碰产品规格与询盘规则。保留旧字段支持逐页迁移与核对，但撤回优先可防止旧快照复活。首页五个视口已经在 [`PAGE-SPECS/homepage.md`](../../PAGE-SPECS/homepage.md) 定义为核心，调整顺序不能使任何核心视口消失。此决定不要求切换到 `next-intl` 或重排全部 App Router 目录。
