# 关键词 + 知识库 + Sitemap → Topic Map 分析规程

更新：2026-10-16。此规程供 AI/研究员复用。目的是把词表变成有业务依据、页面责任明确、意图拆分透明的需求地图，而非自动批量造文章。

## 每次分析的输入

1. **产品知识库**：先读本目录 `README.md`，再读对应产品线文件和权威 Page SPEC。多线词需要同时读公司角色和买家任务。
2. **关键词列表**：优先使用带来源、市场/语言、观察日期、query 状态、已有 SERP 意图的 CSV/表格。不得丢失 evidence status。
3. **当次完整 Sitemap URL LIST**：在分析时从目标站根域名实际获取 `/sitemap.xml` 并展开 sitemap index；记录日期、host、语言、HTTP 状态和 URL 数。保留所有 URL 原文。若用户提供清单，以提供的清单和日期为准。若不能获取则标记缺失，禁止用代码路由或旧 page map 冒充当前 sitemap。
4. **当前站内状态**：读取相关页面 Page SPEC、页面 noindex/批准状态及当前 `STATUS.md` 事项。sitemap 收录本身不等于内容已获准或页面能承接主题。
5. **需求指标（可选）**：只接收有来源的 GSC、Keyword Planner 或付费 provider 数据。记录地区、日期、字段定义和采样覆盖。缺失写 `NOT_AVAILABLE`，禁止猜数。

本项目 2026-10-16 的关键词导出是历史 run 数据：Google US、en-US、桌面；81 条 query 中 11 条手动 SERP 实测，其他为页面可见问句/相关搜索或研究假设。复用前必须遵循日期和证据标记。

## 分析步骤

### 1. 输入核验

核对关键词唯一数、重复词、空 query、产品线、来源类型、观测时间、地区/语言；检查 sitemap URL 是否完整、是否有分页或 sitemap index、是否把 staging URL 当生产站。给出输入缺陷，不在输入缺陷下强行下结论。

### 2. 标注显性搜索意图

用 query 原文指出搜索者明说要做什么、找什么对象、限定什么条件。使用动作+对象表达，例如“寻找可按图评估铝件的供应方”，不要只填 informational/commercial。另给通用漏斗标签（信息/商业调查/交易准备/导航）作为辅助标签，不取代任务描述。

### 3. 推断隐性需求

写出 query 背后的候选工作、风险或决策：为什么现在要搜？搜完要做什么？还缺什么信息才能行动？每项都附可见线索（词面、SERP 页面类型、PAA、业务流程或已知买家工作），标为 `INFERENCE` 并给高/中/低置信。至少提出一个替代解释；证据不足则写 `UNKNOWN`。

### 4. 判读当前 SERP

对已有快照记录查询、市场/语言、日期、设备/位置限制、主导结果类型和特性、广告/本地包/品牌/平台混入、PAA/相关搜索。显性 query intent、隐性买家需求和 Google 当前展示意图分开写。快照缺失的关键词不得声称 SERP 证明意图。

### 5. 聚类到同一买家任务

按“买家任务 + 预期页面类型 + SERP/结果 URL 重叠”合并。相同词根不保证同页；不同词形也可能由同一页完成。若没有已解析的 SERP URL 或页面类型证据，将同页关系标为 `PROVISIONAL`，不要假装聚类确定。

### 6. 对照 sitemap 找页面 owner

逐 cluster 匹配现有 URL：

- `COVERED`：URL 存在、内容和目标任务匹配、索引/语言/业务门槛允许。
- `PARTIAL`：有相关 URL 但遗漏一个买家问题、缺证据、内容/语言/转化流程不符。
- `GAP`：没有合适 URL；先判断应补现有页模块、工具、产品能力还是新页面。
- `CANNIBALIZATION_RISK`：多个 URL 争同一任务，需确定一个主责页并处理内链/canonical。
- `GATED`：有候选 URL 但 noindex、审批、证据或业务能力尚未通过。
- `NO_FIT`：需求与实际业务/责任范围不符，或风险不可接受。

不在 sitemap 的 URL 可能仍存在，但不能判成 sitemap 已覆盖；从路由盘点发现时单独注明“存在但未入 sitemap”。sitemap 中的政策页、thank-you 或 fitment 页也不能只因存在就认定其适合作为 SEO landing page。

### 7. 输出优先路线和未决问题

按事实可承接性、意图匹配、页面缺口/重叠、现有证据、实现成本和不确定性说明优先级。若没有真实需求量数据，不给 volume 排名、traffic 预测或转化承诺。优先级理由需可审计，建议单独列“证据强度”和“潜在商业价值”，避免一个伪精确总分。

## 输出格式

### A. 输入与限制

记录文件、行数、市场/语言、数据日期、sitemap 抓取日期/host/URL 数、缺少的数据和已知采样限制。

### B. Topic Map 总览

按公司/买家任务 → 产品线 → 子主题 → query cluster → 页面 owner 展示。每个 topic 说明阶段（研究/采购筛选/RFQ）、显性意图、隐性意图、SERP 页面意图、证据、置信、当前覆盖状态和下一动作。

### C. 关键词逐行分类表

至少包含：原 query、标准化 query、产品线、query 来源状态、显性意图、隐性需求假设、替代解释、漏斗辅助标签、SERP 证据/缺失、目标页面、sitemap 匹配状态、需要的事实/功能、置信、下一步。

### D. Sitemap 覆盖与 IA 建议

分别列已有页应加强、重复 owner 待裁定、缺失页候选、暂缓/排除主题；给出当前 sitemap URL 原文作为证据。不要直接创建 URL，先看现有页面可否承接。

### E. 事实缺口和研究计划

按必须由业务确认、工程/供应商核验、内容/图权审核、SERP/GSC 进一步观察分组。为每项缺口指定最小取证问题和决策影响。

### F. 不能得出的结论

明确列出本轮无法支持的搜索量、难度、流量预测、真实客户偏好、产品能力或认证主张。

## 可直接复制的 AI 提示词

```text
你是峰徊海外汽车零部件网站的 SEO 研究分析员。请先读取我提供的产品与行业知识库，再读取关键词导出表和本次最新 sitemap URL LIST，必要时查看已提供的 Page SPEC/页面审批状态。

目标：输出可审计的 Topic Map、需求方向和逐词显性/隐性搜索意图，并判断当前页面是否承接，不要写成未经证实的 SEO 文章清单。

规则：
1. 以知识库链接的项目正本和页面规格为公司/产品事实来源；将 FACT、SERP OBSERVED、INFERENCE、UNKNOWN 分开。外部搜索结果、竞品描述和通用行业知识不能提升为峰徊事实。
2. 每个 query 分别写：显性意图（词面任务）、隐性需求推断（为什么搜/要规避何种风险）、替代解释、当前 SERP 页面意图（只有提供 SERP 证据时才判断）、买家阶段、置信度及依据。隐性意图不是读心；证据不足就写 UNKNOWN。
3. 把 sitemap 当作本次抓取时点的现状。逐条引用实际 URL，判断 COVERED / PARTIAL / GAP / CANNIBALIZATION_RISK / GATED / NO_FIT。区分“不在 sitemap”和“页面不存在”。不要拿旧 sitemap、路由源代码或历史 page map 冒充当前 URL 清单。
4. 按买家任务、页面类型和 SERP/结果 URL 重叠聚类，不要只按词根；URL 重叠未经核对时标为 PROVISIONAL。
5. 不推测搜索量、难度、CPC、排名、流量、转化率或市场规模。没有数据就写 NOT_AVAILABLE。
6. 不推断未证实的制造主体、工艺、材料、公差、认证、客户、案例、价格、MOQ、交期、库存、适配、性能或法律承诺。把需要业务/工程核实的事项写成证据缺口。
7. 先判断能否补现有 URL；新增页面只作候选，并说明为什么现有页无法完成同一买家任务。商业机会和证据置信度分开排序。

输出：输入质量与限制；Topic Map；逐词意图表；当前 sitemap 覆盖表；页面 owner/重复风险；内容与产品证据缺口；建议的下一轮 SERP/GSC/访谈取证；本轮不能得出的结论。每个主要结论引用输入文件名、query ID 或 sitemap URL。

输入附件：
- 知识库：<列出文件>
- 关键词导出：<文件及导出日期>
- sitemap URL LIST：<抓取日期、站点 host、文件>
- 当前页面规格/索引状态：<文件或说明>
- 搜索/分析数据：<文件；没有则写 NOT_AVAILABLE>
```

## 验收标准

- 随机抽查 query 能追溯到来源状态和原文。
- 隐性意图有推理线索、替代解释和置信度。
- sitemap 覆盖判断引用当前 URL，缺口不以“AI 觉得应该有”填补。
- 事实主张回链正本；所有未核验主张保持 UNKNOWN/GATED。
- 所有搜索需求指标明确来源与日期，缺失时保留 `NOT_AVAILABLE`。
