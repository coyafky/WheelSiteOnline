## 0. 四条前置

### ⓪ 我们的底本是 2N Forged

**本页面架构不是凭空设计的**，而是以竞品 [2nforged.com](https://2nforged.com)
的 12 页 / 88 个 section 为底本搭起来的。完整清单与逐条取舍（KEEP / CHANGE /
MERGE / HOLD）见 **`2nforged-page-inventory.md`**。

从竞品提炼的六个可复用模式（本文件多处引用）：

| # | 模式 | 我们用在哪 |
|---|---|---|
| M1 | **一个系统服务多页**（一套类名支撑 3 页） | 四条产品线共用一套模板 |
| M2 | **长页尾部必有「路由段」**（「了解完 X 了，接下来去哪」） | 所有长页 |
| M3 | **工艺/结构对比段** | 轮毂线核心段落 |
| M4 | **对号入座段**（「如果你只卖过现货，从这里开始」） | 经销商 / 贴牌 |
| M5 | **攻心段**（「没人敢问供应商的问题」） | 贴牌页 |
| M6 | **索引页用三明治**（页头 ＋ 分类条 ＋ 列表） | `/insights` |

**竞品做错的七件事**（我们明确不学）见该文件 §4，其中三条最关键：
整个目录压一页、公开谈价格、工艺页零 CTA。

### ① 四条平行产品线 —— 这是全站信息架构的地基

| 产品线 | 英文 | 上架就绪度 |
|---|---|---|
| **轮毂** | Wheels | ✅ **可上架**（1018 型号有图） |

**四条线在层级、字号、交互、卡片尺寸上平行。**
轮毂可以有更多子类与单品，**但不设置为其他三条线的父级**。

**本期只有轮毂能做成完整的产品线。** 其余三条先出「能力页」而非「产品页」——
讲清我们能做什么，不列做不到的型号。

### ② 上架门槛：无图不上架

```
1349 型号 → 1018 有图（上架）｜331 无图（不上架）
```

无图型号不建页、不进列表、不出现在筛选结果里。

### ③ 每一页必须回答一个「经销商问题」

经销商来网站不是来浏览的，是来找答案的。每一页都必须能对应到至少一个具体问题，
否则这页不该存在。

### 2.1 `/` 首页

**给谁看**：第一次来的经销商 / 采购。
**要回答**：这是什么公司？能做什么？我该往哪走？

| 序 | 模块 | 要说明的内容 |
|---|---|---|
| 1 | Hero | 一句话定位：峰徊是**四条产品线的铝制部件制造商**（不是只做轮毂）。主 CTA = 获取报价 |
| 2 | 四条产品线入口 | **平行四卡**：轮毂 / EV三电 / 铝制品 / 安全轮胎。卡片尺寸一致，不突出轮毂 |
| 3 | 轮毂精选 | 4–6 个有图的型号 + 快速入口。内容可更深，**但不改变线级** |
| 4 | 其余三条线代表能力 | 每条 1 个能力说明（不列型号，因为没有） |
| 5 | 制造与质量证据 | 工艺能力（旋压 / 低压铸造 / 锻造）+ 质量证据 |
| 6 | 定制开发流程 | 从图纸/样件到成品的步骤 |
| 7 | 技术与见解 | 2–3 篇最新文章 |
| 8 | 结尾 CTA | 获取报价 |

**完成标准**：经销商能在首屏判断「这家能不能做我要的东西」，并知道下一步点哪。

### 2.3 `/products/wheels` 轮毂目录 ★★

> **完整架构见 `wheel-catalog-page.md`**（六段式，1018 型号 + **7 组筛选器**）。
>
> **🔴 实测发现**：竞品的 `/products/`（产品目录）**是空的**

> **它真正可浏览的是 `/wheel-gallery/`，只有 25 个设计、3 组单选筛选器。**
> **→ 我们的目录页复杂度是它的 40 倍，必须自己设计而不是照抄。**

**给谁看**：找具体型号的经销商。
**要回答**：你们有哪些轮毂？哪些符合我的需求？

| 序 | 模块 | 要说明的内容 |
|---|---|---|
| 1 | 页头 | 轮毂产品线定位：15–23 英寸、旋压/低压/锻造 |
| 2 | **筛选器** | 见下方 §2.3.1 |
| 3 | 型号网格 | 卡片：主图 + 型号 + 尺寸 + 表面处理。**只有有图的 1018 个** |
| 4 | 分页 / 加载更多 | — |
| 5 | 数据说明 | 明确标注「规格以最终确认为准」，附询盘入口 |

#### 2.3.1 筛选器规格（受数据覆盖率约束）

| 筛选项 | 数据支持 | 能否做 |
|---|---|---|
| 尺寸（15–20寸 / 越野 / HP） | 1349 / 1349 | ✅ 必做 |
| PCD / 孔距 | 1349 / 1349 | ✅ 必做 |
| 表面处理 | 1349 / 1349 | ✅ 必做 |
| 偏距 ET | 1349 / 1349 | ✅ 可做（需先归一化范围） |
| 中心孔 CB | 1349 / 1349 | ✅ 可做 |
| **制造工艺** | **512 / 1349** | ⚠️ 可做，但**必须标注「部分型号未标注」**，否则筛掉的结果会让用户误以为没有 |
| **设计系列** | **762 / 1349** | ⚠️ 同上 |
| 车型适配 | **0 / 1349** | ❌ **绝对不做** |

**⚠️ 筛选器的一条铁律**：缺数据的型号在筛选时**不能被静默排除**。
选了「旋压」后，837 个未标注工艺的型号不能凭空消失 —— 要么明确提示
「另有 N 个型号未标注工艺」，要么把这些型号单列一组。
**静默排除 = 让经销商以为我们没有那个产品。**

| 序 | 模块 | 要说明的内容 |
|---|---|---|
| 1 | 面包屑 + 型号名 | — |
| 2 | 图库 | ★ **只展示 1 张主图**（用户定案，1018 页版式统一） |
| 3 | 摘要 | 一句话卖点 + 主要应用场景 |

**⚠️ 三个纪律**：
1. **规格必须来自该型号的实际 variant 数据**，不得用系列通用值。

3. **无图的型号不生成此页**（上架门槛）。

## 3. 全局规则

### 3.1 ★ 产品线页模板（九段式）

**这是从竞品 `monoblock-wheels`（17 段）与 `custom-forged-wheels-for-dealers`
（14 段）的骨架提炼出来的**，四条线共用，保证平行。

```
产品线页 = ① 页头定位
         → ② 这条线是什么（定义）          ← 学 M2.6 第 1 段
         → ③ 给谁用 / 对号入座             ← 学 M4
         → ④ 我们能做什么（能力）
         → ⑤ 规格 / 型号                   ← ★ 有数据才做
         → ⑥ 工艺 / 结构对比               ← 学 M3
         → ⑦ 常见问题 FAQ
         → ⑧ 路由（下一步去哪）             ← 学 M2
         → ⑨ 询盘 CTA
```

**四条线各自能做到第几段**（兑现上架门槛 DEC-013）：

| 段落 | 轮毂 | EV三电 | 铝制品 | 安全轮胎 |
|---|---|---|---|---|
| ② 定义 | ✅ | ⚠️ 仅语料 | ⚠️ 仅语料 | ⚠️ 仅语料 |
| ⑤ **型号/规格** | ✅ **1018 型号** | ❌ 无 | ❌ 无 | ❌ 无 |
| ⑥ 对比 | ✅ | ⚠️ 待写 | ⚠️ 待写 | ⚠️ 待写 |

→ **其余三条线只出到「能力页」（①③④⑦⑧⑨），⑤⑥ 留空。**
**不要用竞品的型号去填我们的空** —— 那是最容易犯的错。

**⚠️ 律**：四条线**平行**，轮毂不设为其他三条的父级。

**⚠️ 三条能力线已各自出完整文档**（`ev-components-page.md` / `custom-aluminum-page.md` /
`safety-tires-page.md`）。**它们对模板有一处共同偏离**：模板的 ⑤「型号/规格」段
在本期全部留空（无型号数据），但**各自用一段顶替** ——
EV三电用「③ 可承接零件清单」，铝制品用「④ 能力边界」，
安全轮胎用「③ 痛点 + ④ 原理」。**这不是偏离纪律，是把空位换成真内容。**

### 3.2 每页必须有询盘入口

任何承认真实浏览意图的页面，底部都要有进询盘的路径。
**但不得做成弹窗骚扰** —— 静态入口即可。

### 3.3 中英双语

一级导航有语言切换。文案底座（语料库）本身就是中英对照。

### 3.4 SEO

- 每页必须有唯一 title / description
- 产品页用 `Product` 结构化数据
- 无图型号不生成页面 → **也不进 sitemap**
