## 0. 这页的定位：**它是「能力」页，不是「产品」页**

| 常见做法（要避免） | 本页实际要做的 |
|---|---|
| 列一堆「我们做过的零件」 | **讲清「什么输入能进流程」** |
| 说「我们可以做任何铝件」 | **给边界** —— 没边界的供应商没人敢用 |
| 用轮毂的工艺图充门面 | **用开发流程图**（图纸 → 打样 → 验证 → 量产） |

**⚠️ 本页面对一个根本困难**：语料库里「铝制品」类别**只有 4 条术语**
（端盖 / 控制臂 / 转向节 / 轻量化结构件）。
**这不足以撑起一个产品目录** —— **所以本页不能走「产品目录」路线。**

**→ 本页必须走「流程 + 边界」路线。** 而这恰好也是 B2B 定制生意的本质：
客户买的不是零件，是**「把我的图变成件」这件事本身**。

**★ 本页的核心资产是一张图，不是一份清单。**

## 1. ⚠️ 与 `/products/ev-components` 的分工（必须现在切清）

**这两页共用同一条主线**（图纸 / 3D 数据 / 样件 → 开发流程），
**不切清就会写成两页一样的东西。**

| | `/products/ev-components` | **`/products/custom-aluminum`（本页）** |
|---|---|---|
| 对象 | **新能源三电壳体**（有明确定义的一组件） | **任何铝合金定制件**（无先验边界） |
| 行业 | 汽车（NEV） | **不限行业**（汽车 / 工业 / 消费） |
| 客户 | 整车厂 / Tier1 | **有图纸的采购、产品公司、工程公司** |
| 页面的锚 | **散热 · 密封 · 精度** | **输入方式 · 边界 · 流程** |
| 核心段落 | ③ 可承接零件清单 | **③ 四类输入 + ④ 边界** |
| 术语来源 | 20 项 EV 术语 | **4 项铝制品术语** |

**⚠️ 一条判定线**：
**如果客户要的东西「有名字」（壳体、端板、水冷板）→ 走 ev-components；
如果客户要的东西「只有一张图」→ 走本页。**

**→ 本页第一段就要写清这条分流**，否则客户会走错页。

## 3. ⚠️ 一个必须做的取舍：4 条术语怎么用

**问题**：铝制品类别只有 4 条术语（端盖/控制臂/转向节/轻量化结构件）。
**如果做成「产品目录」→ 一页只有 4 个卡，页面很空，且暴露我们产品线单薄。**

**→ 决策：这 4 条不做成产品网格，改做成「典型件」举例，且与「行业」绑定。**

### 3.1 呈现方式：**按应用场景分 3 组**（不是按零件分）

| 组 | 举例零件 | 场景描述（要新写） |
|---|---|---|
| **动力与传动** | 端盖 · 支架 | 与三电/传动配套的机加件 |
| **底盘与车身** | 控制臂 · 转向节 · 连接件 · 轻量化结构件 | **原文备注就是「底盘与车身」** |
| **通用机加件** | （语料库无） | ⚠️ **暂不写** —— 无来源不写 |

**⚠️ 只有前两组有语料支撑。第三组空着，不编。**

### 3.2 每组卡的写法（M1 一个系统服务多页）

```
┌─ 动力与传动 ────────────────┐   ┌─ 底盘与车身 ────────────────┐
│ 端盖 End cover              │   │ 控制臂 Control arm          │
│ 支架 Bracket                │   │ 转向节 Steering knuckle     │
│                             │   │ 连接件 · 轻量化结构件        │
│ 与三电/传动系统配套的        │   │ 底盘与车身用轻量化           │
│ 铝合金机加件                │   │ 铝合金结构件                │
└─────────────────────────────┘   └─────────────────────────────┘
```

**⚠️ 每卡下方必须有一行**：「以上为典型件举例，**实际按图评估**」。见 §4。

**要写三段**：

### ③ ★ 四类输入（本页差异化段之一）

**核心句（峰徊 P15）**：

> **图纸、3D 数据或样件，都能进入开发流程**
> Start with a Drawing, 3D Data or Physical Sample

**展开成四张卡**（第 4 类由 P3 的「逆向工程」支撑）：

| 输入类型 | 中文 | 英文 | 我们要客户提供什么 |
|---|---|---|---|
| 1 | **2D 图纸** | 2D Drawing | 三视图 + 关键尺寸 + 公差要求 |
| 2 | **3D 数据** | 3D Data | STEP / IGES 等中性格式 |
| 3 | **实物样件** | Physical Sample | 寄样 + 使用条件说明 |
| 4 | **只有参考件**（逆向） | Reverse Engineering | **我们有逆向工程能力**（峰徊 P3/7） |

**⚠️ 第 4 类是本页最容易被忽略、但客户最需要的一类** ——
很多采购手里只有竞品的一个件，没有图。**明确写出这一条，能接住一批客户。**

### ④ ★★ 能力边界（本页最重要的一段）

**⚠️ 这一段的写法与全站其它页相反：它要「划掉」东西。**

**为什么**：铝制品定制的最大成本事故是「**走完评估才发现做不了**」。
**主动划边界 = 减少双方浪费 = 建立专业感。**（同 M5 攻心段的逻辑）

| 我们要写出来 | 内容 |
|---|---|
| ✅ **能做** | 铝合金/镁合金 · 铸造与锻造路线 · CNC 精加工 · 表面处理 · 可按项目组合工艺（峰徊 P7） |
| ❌ **不做** | ⚠️ **待丰怀确认后填写** —— 例如超小件？超大批量？纯钣金？非铝材质？ |
| ⚠️ **需评估** | 尺寸/重量/复杂度上限之外的件（**边界数字待确认，见 §6**） |

**⚠️ 「不做」这一栏现在是空的** —— **不能编**。
但也**不能省掉这一栏** —— 它是本页结构的骨架，等丰怀给答案就能填。

**★ 收尾句直接用峰徊 P7 原文**（见 §2.4）。
