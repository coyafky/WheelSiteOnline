# Deep Discuss

1. 用一句话复述期望结果与目标用户。
2. 分开列出已确认事实、假设、风险、非范围和待确认项。
3. 对每个会改变数据模型、页面结构、公开主张、部署、安全或权限的歧义提出具体问题，并说明选项与代价。
4. 输出讨论记录和用户决定，更新对应规格、MASTER 或 DECISIONS。
5. 用户明确“开始实施/确认进入 Phase 5”前，不创建实现代码、不移动任务到 active、不创建批次 PR。

现有项目硬约束和不可逆操作确认规则优先。Deep Discuss 不是实现计划，也不能把未决定事项写成完成。
