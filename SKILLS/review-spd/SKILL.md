# Review SPD

## 比较基点

开始前明确审查对象：

- 未提交修改：工作树相对 HEAD；
- commit 范围：明确 base..head；
- 分支：相对目标分支；
- PR：PR 的 base/head 与实际文件范围。

如果基点不明，声明只能审查当前 diff，不能证明完整范围。

## Findings-first

先按 P0、P1、P2、P3 输出可执行问题，再分别给出规范轴和规格轴结论。格式固定：

```text
[P1] 标题
文件与行号：
触发条件：
实际影响：
修复方向：
```

规范轴检查项目规则、TypeScript/Next 约束、内容接缝、证据纪律、发布门槛、安全、隐私、最小权限、测试与回滚。规格轴逐条对照来源规格、任务、接口契约、S.U.P.E.R、验收和非范围，检查遗漏、误实现和范围蔓延。

没有可执行问题时明确写“未发现阻断问题”，并列出尚未覆盖的验证边界。评审默认只读，不自动修改代码、不自动提交或创建 PR。
