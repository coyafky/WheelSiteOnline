# Project

## Project Name

丰怀锻造轮毂独立站（Fenghuai Forged Wheels — Independent Site）

## Background

丰怀是一家锻造轮毂制造商，客户是经销商与分销商，不做终端零售。公司目前没有
一个可以发给经销商看的自有网站，没有结构化的产品数据，询盘渠道也只有邮箱和
即时通讯工具。

**本仓库的前端是克隆来的，不是自研的。** 它以竞品
[2nforged.com](https://2nforged.com) 的 UI 为蓝本，用仓库自带的
`clone-website` 技能逆向重建为 Next.js 代码（竞品本身是 WordPress 主题
`wp-theme-2nforged-theme`，结构侦察见
`docs/research/2nforged-reference.md`）。克隆达到的是「结构完整」——
56 个页面、21 个内容模块、设计令牌与动效系统齐备。

**当前状态：前端与后端都还没做完。**

| 层 | 规划 | 实际 |
|---|---|---|
| 前端 | Next.js 16 App Router | ✅ 已建，但内容仍是占位的，**且文案与信息架构是照搬竞品的，未按丰怀业务改写** |
| 内容后端 | 无头 WordPress | ❌ 未接通，`src/content/*.ts` 仍是静态 TS |
| 部署 | OpenNext | ❌ 未接入，仓库里**没有任何 OpenNext 依赖或配置** |

所以这个项目要补的是三件事：**把克隆来的 UI 改造成丰怀自己的**、
**把内容层接到 WordPress**、**把部署形态定下来**。克隆只是起点，不是成果。

## Goal

为丰怀上线一个公开、可生产使用的 B2B 锻造轮毂站点，满足五点：

1. **把克隆来的 UI 改造成丰怀自己的** —— 文案、信息架构、页面取舍都按丰怀的
   实际业务重写，不再是竞品的样子。
2. 经销商在两分钟内、不用打电话就能看懂产品范围并提交询盘。
3. 内容由 WordPress 提供，公司不依赖开发者就能更新产品与文章。
4. 用 OpenNext 部署，且部署形态与询盘系统的运行时需求一致。
5. 任何未经工程确认的数据，都不作为规格发布。

## Scope

**包含**

- **前端改造**：在克隆骨架上按丰怀业务重写文案与信息架构；决定哪些竞品页面
  保留、哪些合并、哪些删掉。
- 公开站点：产品系列、SKU 页、画廊、适配（fitment）页面、资源文章、
  经销商计划、政策页。
- 一套无头 WordPress 作为内容唯一事实源。
- 连接两者的内容抓取层。
- **OpenNext 部署链路**：从选型到构建到上线。
- 询盘管线：捕获、持久化、销售分配、邮件通知。
- 域名、TLS，以及以上全部内容的运维手册。

**不包含**

- 我们自研的通用后台或 CMS 界面。编辑器就是 WordPress。
- 电商结算。本站刻意做成询盘站 —— 见 DEC-003。
- 客户账号、订单历史，或任何需要登录的功能。
- 任何丰怀未确认的公司事实。

## Constraints

**技术**

- Next.js 16 App Router、Turbopack、React 19、Tailwind v4、TypeScript strict。
- **部署走 OpenNext**，且必须与询盘系统的运行时需求一致 —— `/api/inquiries`
  是运行时路由，需要 Node/Workers 运行时，**不能是纯静态导出**（见 DEC-009）。
- 内容目前是 `src/content/` 下的类型化模块；该目录就是接缝，必须能在不修改
  任何组件的前提下被替换。
- 生产构建必须可跨平台编译 —— `NEXT_PUBLIC_APP_URL` 的陷阱见 `DECISIONS.md`。
- 本机允许使用 macOS 专有构建工具；服务器只跑校验与 `next build`。

**来源与法务（克隆带来的约束）**

- 前端 UI 是竞品 2nforged.com 的复刻。**可借鉴结构、排版与交互模型，
  但不得搬运其文案、图片、视频、品牌标识。** 上线前必须逐项清扫残留的
  竞品内容（见 DEC-010）。
- 竞品的 WordPress 主题名、图片路径、站点标题等痕迹不得出现在产物中。

**品牌**

- 配色为石墨/钢灰底加炉火琥珀强调色。组件内不得出现裸 hex 值，令牌统一定义
  在 `src/app/globals.css`。
- 这是 B2B。不用零售电商话术，不制造紧迫感，不展示价格。

**数据与证据**

- 适配数据是安全关键项。`src/content/fitment.ts` 只能发布起始范围；偏距
  （offset）、孔距（PCD）、中心孔、载荷等级在逐底盘确认之前一律不发布。
- 站点上每个数字都必须可溯源。占位的商业数字不得上线 —— 见 `PLACEHOLDER`
  清查要求。

**合规**

- 站点面向出口市场。法律文件需由合格律师审核，不得使用凭空编造的值。
- 询盘数据属于个人数据。留存期、存储位置与第三方处理方（Resend）必须在
  隐私政策中披露。

**预算**

- 托管控制在小型 VPS 或免费/低成本额度内。不为一个面向经销商的站点承担
  按席位计费的 SaaS 成本。

## Definition of Done

以下**全部**满足时，项目才算完成：

1. **前端已完成业务改造** —— 站点上不再有竞品的文案、图片或品牌标识；
   信息架构按丰怀的实际产品线重新决策过。
2. `src/content/` 中每一个 `PLACEHOLDER` 都已解决，或该说法已被删除。
3. 产品与文章在 WordPress 中编辑后无需部署即可在站点生效。
4. **OpenNext 部署链路已跑通**，且 `/api/inquiries` 在该部署形态下可用。
5. `/contact` 提交的询盘能带着产品上下文送达指定销售的收件箱，已持久化，
   且能在邮件失败时存活。
6. 适配标记由工程部门设置，而不是我们。
7. 法律文件带有律师签字确认。
8. `npm run check` 全绿，且部署手册由**非作者本人**实际执行过一次。

## Success Metrics

| 指标 | 目标 | 衡量方式 |
|---|---|---|
| **前端去竞品化** | 0 处竞品残留（文案/图片/品牌/路径） | 全仓扫描 `2nforged`、竞品图片路径、竞品品牌名 |

| 内容流转速度 | 新增一个 SKU 无需改代码或部署 | WordPress 发布到站点生效的耗时 |
| 证据纪律 | 0 条未确认规格被发布 | `PLACEHOLDER` 清查 + 适配标记审计 |
| 站点健康 | 全部路由 200，构建干净 | 每次变更跑 `npm run check` |
| 页面开销 | 无页面发起无人引用的图片请求 | 构建产物审计 |

## Assumptions

以下假设影响了计划，但尚未得到客户确认，故显式标注。

- **公司名为「丰怀」，品牌定位是面向出口的 B2B 锻造轮毂。** 取自仓库名与现有
  内容。*未经丰怀确认。*
- **`src/content/` 中现有的商业数字是合理的行业数值，不是有来源的主张。**
  交期、产能范围、起订量、载荷等级都需要客户确认后才能上线。
- **尚未绑定真实域名。** 询盘管线方案中提到发信子域 `notify.`，这以拥有域名
  控制权为前提。
- **丰怀能够自建或授权一个 WordPress 实例。** 整个内容层都依赖这一点，目前
  尚未确认。
- **克隆的 UI 可以合法作为起点，但不能原样上线。** 已落成硬约束（文案/图片/
  品牌标识不得搬运），但最终可用性判断应由法务确认。
- **OpenNext 的具体落地形态（Cloudflare Workers / AWS Lambda / 自托管 Node）
  尚未选定。** 仓库里目前没有任何 OpenNext 配置，本文件只把它记为既定方向。
