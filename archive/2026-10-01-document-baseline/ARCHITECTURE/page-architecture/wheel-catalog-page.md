## 0. 🔴 先说一个实测的重大发现

**竞品的「产品目录页」是空的。**

| 竞品页 | 实测 |
|---|---|
| `/products/`（**产品目录**） | 单 section 4,770px，**筛选器是 `catalog-filter-empty`**，label 写着：<br>*"**No products assigned to this category yet.** Existing products will appear here after…"* |
| `/wheel-gallery/`（**画廊**） | 3 段，**筛选器完整可用，25 个设计** |

**→ 竞品真正的「可浏览目录」是 `/wheel-gallery/`，它的 `/products/` 是个空壳。**
（这解释了为什么它的 `/products/` 要 26 个 H2 撑长度 —— 没产品可列。）

**对我们的意义**：
- **竞品的目录页没有可学的「列表结构」** —— 它只有 25 个设计，我们 1018 个
- **它的筛选器只有 3 组**（Construction / Style / Finish）—— 它有 12 组吗？没有，WheelPros 才有
- **我们要同时学两家**：结构学 `/wheel-gallery/`，筛选器广度学 WheelPros

```

rendered:  300 × 420     （同比例）
ratio:     0.71
alt:       "2N Forged custom forged wheel design reference 01 view 02 with
            Matte gunmetal, Monoblock forged, …"
```

**★ 它的卡片图是竖构图 0.71（≈ 1:1.4），不是方形。**
alt 里带齐了 `表面处理 + 工艺 + 代号`（**SEO 友好**）。**这两点都值得学。**

### 1.3 ⚠️ 但我们不能用 0.71 竖构图

| | 竞品 | 我们 |
|---|---|---|
| 图源 | 商业精修竖构图 1714×2400 | **目录图**（正方，见 `assets/README.md`） |

**→ 我们的卡片图必须用 1:1 正方**（与详情页统一），否则目录图会被裁。

## 3. ★ 七组筛选器（核心）

**严格遵守 `wheel-browsing-and-fitment-pages.md` §2.2 的定义。**

### 3.1 筛选器清单（按用户点选优先级）

| 序 | 筛选项 | 类型 | 覆盖 | 备注 |
|---|---|---|---|---|
| 1 | **尺寸（直径）** | 多选 | **100%** | 15–20 寸，数值排序 |
| 2 | **PCD / 孔距** | 多选 | **100%** | ★ 采购方最高频 |
| 3 | **孔数** | 多选 | **100%** | 派生自 PCD，**须白名单** |
| 4 | **工艺** | 多选 | ⚠️ **38%** | ★ 旋压/低压/锻造 |
| 5 | **偏距 ET** | 范围滑杆 | **100%** | 实测 **0 ~ 46**（32 个不同值） |
| 6 | **中心孔 CB** | 多选 | **100%** | 实测 **41 个去重值**（66.1 / 73.1 / 110.1 …） |
| 7 | **表面处理** | 多选 + 分组 | **100%** | 实测 **679 个去重值**，见 §3.4 |

### 3.4 ⚠️ 表面处理是 679 个值，不是「20+ 种」

**我在别处写「20+ 种」是错的。** 实测：

```
表面处理去重值: 679 个
```

**679 个值无法直接做成筛选列表。** 必须先分组（照竞品的 Solid / Brushed 二分法）：

| 组 | 实测数量 | 判定规则 | 样例 |
|---|---|---|---|
| **单色** | **283** | 无「压盘/车面/全涂」 | 古铜 / 枪灰 / 哑黑 / 银色 / 金色 |
| **车面** | **217** | 含「车面」「车边」 | 黑色车面 / 高亮黑车边 / 亮黑车面 |
| **全涂装** | **152** | 含「全涂装」「全涂」 | 白色全涂装 / 哑黑全涂 |
| **压盘双色** | **27** | 含「压盘」 | 哑黑+哑黑压盘 / 哑灰+原铝压盘 |
| **合计** | **679** | | ✅ 与去重数吻合，无遗漏 |

**⚠️ 但实测也发现数据脏点** —— 单色组里有这些：

```
磨砂096古铜 ｜ 古铜色+古铜色透明漆 ｜ 磨砂古铜（(17#古铜)）+古铜精油边
喷砂亚古铜漆 ｜ 亚黑 ｜ 亮黑色+车内边
```

**「亮黑色+车内边」是双色却被归入单色**（没写「车面」二字）。
→ **分组规则要靠关键词表 + 人工复核**，不能纯正则。
**这是 `tech-architecture` 清洗步骤要做的事，不是筛选器的事。**

### 3.5 另外两个实测修正

| 项 | 我原先写的 | 实测 |
|---|---|---|
| ET 范围 | −12 ~ +48 | **0 ~ 46**（32 个值） |
| CB 值数 | 未标 | **41 个** |
| PCD 值数 | 未标 | **41 个** |

**❌ 明确不做**：
- **Fitment / 车型适配** —— `suitableVehicles` 全空，**做了就是骗人**
- Brand —— 自有品牌无此维度
- Material —— 与 `process` 重复

### 3.2 ★ 三条筛选器铁律

#### 铁律一：缺数据必须显式暴露，不能静默排除

**`process` 只有 512/1349 有标注。**

```
选「旋压」时 →
  ❌ 错误：结果 = process === "旋压"（837 个未标注的凭空消失）
  ✅ 正确：显示「旋压（350）」+「另有 837 个型号未标注工艺」[默认勾选]
```

**静默排除 = 让经销商以为我们没有那个产品。** 这是最贵的一类错误。

#### 铁律二：孔数派生必须走白名单

实测抓到的脏数据：

```
120孔 → 2 个型号   ← ❌ 畸形值（来自 PCD 写成 120*... 之类）
```

```js
const LUG_WHITELIST = new Set(["4", "5", "6", "8", "10"]);
const deriveLug = (pcd) => {
  const n = String(pcd).split("*")[0].trim();
  return LUG_WHITELIST.has(n) ? n : null;   // 非白名单 → null，不猜
};
```

→ 这 2 个型号进「未标注孔数」分组。

#### 铁律三：尺寸必须先归一化

```
脏值：17寸-2  17寸-3  18寸-2  HP轮毂  越野款
归一化：17寸  17寸    18寸    HP      越野款
```

**产出两套独立维度**：**直径**（15–20，可排序）+ **款式**（HP/越野款，单列一组）。

**✅ 归一化已实测无损**：`18寸437 ｜ 19寸346 ｜ 17寸242 ｜ 15寸106 ｜ 20寸86 ｜ 16寸75 ｜ 越野款42 ｜ HP15` = **1349 ✅**

### 3.3 交互规范（学 WheelPros 的结构，改它的行为）

| 项 | WheelPros | 我们 |
|---|---|---|
| 语义 | **多选**（复选框） | ✅ 多选 |
| 超长列表 | **Show More 折叠** | ✅ 学 |
| 全清 | `Clear All` | ✅ 学 |
| 移动端 | — | **抽屉 Drawer**（学竞品 `gallery-mobile-filter-trigger`） |
| URL 同步 | ?p=2 分页 | **★ 筛选条件进 URL**（可分享、可 SEO） |

**★ URL 同步是我们必须做而两家都没做好的** —— 采购方会想把「5×114.3 的 19 寸旋压」发给同事。

## 4. ★ 型号卡片的三种形态

**1018 个型号，卡片信息密度必须控制。** 学 WheelPros 的「4 行极简」：

### 4.1 标准卡片（有图型号）

```
┌─────────────────┐
│                 │
│   [1:1 单图]     │  ← 正方，object-fit: contain
│                 │
├─────────────────┤
│ 1081X           │  ← 型号（H3）
│ WEDS TC005 旋压  │  ← styleName（有则显示）
│ 15×7 · 4×100    │  ← 规格摘要（1 行）
│ 白色全涂装 · 枪灰 │  ← 表面处理（截断）
└─────────────────┘
```

**4 行，与 WheelPros 一致。** 详细规格留给详情页。

### 4.2 ⚠️ 三种形态必须区分

| 情况 | 数量 | 呈现 |
|---|---|---|
| **1 张图** | **513（50%）** | 标准卡（单图就是全部） |
| 多张图 | 538 | 标准卡（**目录仍只取第一张**，见 DEC-014） |
| **无图** | **331** | **不生成卡片**（上架门槛 DEC-013） |

**★ 因为 DEC-014（单图展示），三种形态在目录页合并成一种 —— 这正是不做多图的价值。**

### 4.3 卡片图片规范

| 项 | 规格 |
|---|---|
| 比例 | **1:1 正方**（⚠️ **不用竞品的 0.71 竖构图**，目录图是正方） |
| object-fit | `contain`（不能 cover，轮毂是圆的会切边） |
| 尺寸声明 | 显式 `width`/`height`（防 CLS） |
| 加载 | 首屏 6–8 张 `priority`，其余 `lazy` |
| 格式 | WebP |
| **alt** | **★ 学竞品：带齐 `型号 + 工艺 + 表面处理`** |

**竞品的 alt 范本**：
> *"custom forged wheel design reference 01 view 02 with Matte gunmetal, Monoblock forged"*

**我们的**：
> `1081X 轮毂 — 15×7 · 4×100 · 旋压 · 白色全涂装`

**⚠️ 不要写 `product-1.png` 这类无价值描述。**

## 5. 网格布局与分页

### 5.1 列数（1018 个型号决定的）

| 断点 | 列数 | 理由 |
|---|---|---|
| 1440+ | **4 列** | 1018 个，2 列要滚 500 屏 |
| 1024 | 3 列 | |
| 768 | 2 列 | ⚠️ **竞品在此溢出**，见下 |
| 390 | 2 列（紧凑） | 或 1 列大图 |

**⚠️ 竞品 `/wheel-gallery/` 在 768 断点实测横向溢出**（`2nforged-page-inventory.md` §4 A5）。
**→ 筛选栏 + 网格的平板竖屏布局必须专门测。**

### 5.2 分页 vs 加载更多

| 方案 | 优 | 劣 |
|---|---|---|
| **页码**（WheelPros） | 可分享、可 SEO、可回退 | 交互老 |
| 加载更多 | 顺滑 | 无法深链 |
| 无限滚动 | 最顺 | **无法深链、SEO 差** |

**→ 选「页码分页」**（学 WheelPros）。B2B 采购会想直接跳到第 12 页，也可能想分享「第 3 页」。

**每页 24 个**（4 列 × 6 行）→ 1018 ÷ 24 ≈ **43 页**。

**★ 但更好的是「筛选后数量少时自动切换」**：
- 结果 > 48 → 分页
- 结果 ≤ 48 → 一屏显示完，不显示分页
