# 轮毂详情页 Page 架构（单品页）

> **本文件定义我们最核心的单品页：`/products/wheels/[model]`。**
>
> 底本 = 竞品 [2N Forged 的 `/wheel-products/n-100rs/`](https://2nforged.com/wheel-products/n-100rs/)
> —— 竞品全站 **只有这一种单品页**（`/wheel-products/<slug>/`）。
>
> 这是我们要建的 **1018 个页面**的模板。**一个模板错，1018 页都错。**

- 版本：v1.0
- 建立日期：2026-10-01
- 上位：`README.md` §2.4 ｜ `../tech-architecture/README.md` §1.2

## 0. 先认一个事实：竞品的单品页**不是数据驱动的**

读完竞品 `/wheel-products/n-100rs/`，最关键的观察：

|  | 竞品单品页实际是什么 | 我们要做的 |
|---|---|---|
| 本质 | **「设计 + 询盘表单」单页** | **规格数据中心 + 询盘** |
| 规格 | ❌ **一个数字都没有** | ✅ 逐 variant 列全 |
| 尺寸 | 文字写「16-26 inch available」（**范围**） | ✅ **实际有货的尺寸** |
| PCD/CB/ET | ❌ **无** | ✅ 有真实数据 |
| 表单 | 「Diameter / Width / Offset（可选）」**客户自己填** | ✅ **从规格里选** |

**竞品的做法是「我不知道你的车什么规格，所以你自己填」。
我们的做法是「我有 3485 个 variant 的真实规格，你选就行」。**

### ⚠️ 这是个根本差别，不是细节

竞品把「定制」当卖点 —— 所以它的单品页是**一个设计图 + 一个询价表单**，
规格交给客户填。**它有 665 个轮毂却没有一个能查规格的页面。**

我们能做**真规格页**（`assets/` 有 3485 个 variant 的 size/PCD/ET/CB/finish）。

**→ 结论：竞品单品页只能「借结构」，不能「借内容」。**
它的 6 段骨架可用，但第 4 段（规格）必须我们自己长出来 —— 且这是**整页的核心价值**。

## 3. 逐段内容设计

### ① 面包屑

```
Home > 轮毂 (Wheels) > 1081X
```

**✓ 必做**：`BreadcrumbList` 结构化数据（SEO）。
**✓ 四级也支持**：若从车系页进来 → `Home > 轮毂 > 坦克 > 1081X`。

---

### ② 图库 —— ★ 只做单图展示（用户 2026-10-01 定案）

**决策：每页只展示 1 张主图。不做缩略图条、不做轮播、不做多角度切换。**

**为什么这个决定是对的** —— 实测数据（严格按 `model` 匹配）：

| 图数 | 型号数 | 占比 |
|---|---|---|
| **1 张** | **513** | **50%** |
| 多张 | 538 | 53% |
| 0 张 | 298 | （不上架） |

**⚠️ 关键：一半的型号只有 1 张图。**

如果按竞品做「主图 + 缩略图条」：
- **513 个型号（50%）会显示一个只有一张的缩略图条** —— 看起来像图库坏了
- 要为另外 538 个型号实现轮播/切换逻辑 —— **一半页面用不上，一半页面不值得**

**单图展示让 1018 个页面获得完全一致的版式** —— 这才是可维护的。

**★ 这个决策还顺带解决了另一件事**：竞品的图库（3 张大图 1400×1400 + 3 张缩略图 180×180）
是**精修商业摄影**。我们的是**目录图**（命名即产品代码，见 `../tech-architecture` §1.3）。
**目录图放大多倍地展示，不如一张干净的主图 + 完整的规格表。**
**我们的强项是规格，不是摄影。** 把版面资源给规格表更划算。

#### ②.1 单图展示规范

| 项 | 规格 |
|---|---|
| 容器 | **1:1 正方**，宽度撑满内容列（不设最大宽度上限） |
| 图片 | `object-fit: contain` —— **不能 `cover`**（轮毂是圆的，cover 会切掉边缘） |
| 尺寸声明 | 显式 `width` / `height`（防 CLS） |
| 加载 | **首屏图 `priority`**，不给 `loading="lazy"` |
| 格式 | **WebP**（唯一格式，365 张 PNG 已删，见 DEC-011） |
| 兜底 | 走 `hasRender` 模式渲染品牌占位，**不发 404 请求** |
| **alt** | **必须带真实型号**，如 `1081X 锻造轮毂侧面` —— 不写 `product-1.png` 这类无价值描述 |

#### ②.2 ⚠️ 多出来的 1693 张图怎么处理

**不删除。** 它们在 `assets/wheel-images-webp/` 里，网页不用而已。

| 用途 | 说明 |
|---|---|
| **画廊页** | 多角度图可作为「同款不同角度」的展示素材（未来） |
| **详情页重做时** | 若将来要做多图，素材已在 |
| **单张选择** | 每页**固定取第一张**（按文件名排序的第一个），规则确定性、可复现 |

**⚠️ 不要手工挑图** —— 1018 个页面手挑不可能维护。
**规则 = 按文件名自然排序取第一个**，生成脚本执行。

#### ②.3 与竞品对比

| | 竞品 N-100rs | 我们 |
|---|---|---|
| 图数 | 3 张大图 + 3 缩略图 | **1 张主图** |
| 拍摄 | 商业精修 | 目录图 |
| 版面重心 | 图片 | **规格表** |

**这不是「我们做得差」，是「我们把版面给了更重要的东西」。**

### ④ 标题区

**竞品的做法**：

```
H1:  N-100rs
副:  Inspired by Modern European Performance Styling
正文: modern forged design featuring sharp multi-spoke geometry and a deep
      concave profile — capturing the essence of elite European performance
      wheel styling while offering fully customizable fitment and finishes.
```

**⚠️ 竞品的文案有商标风险** —— "capturing the essence of **elite European performance** wheel styling"，
而它的 `N-200RS` 描述直接写 "**echoes the look of legendary German performance wheels**"。
**这是典型的「暗示复刻」话术。我们不能学。**

**我们的标题区**：

```
H1:  <型号>                       如 1081X
副:  <styleName>                  有这个字段时才显示
正文: 一句话 —— 这条产品的客观定位
```

**⚠️ 三条纪律**：
1. **不写「灵感来自 X」式话术** —— 那是暗示复刻，商标风险
2. **不写我们没有的参数**（如竞品的 "deep concave"）
3. 副标题**只在 `styleName` 存在时显示**（覆盖率 762/1349）

### ⑤ ★ 规格表（竞品没有，我们的核心）

**这是整页最有价值的一段，也是竞品最大的空白。**

**结构**：按 **variant** 展开（一个 model 有多个 variant）

```
型号 1081X   （2 个可下单配置）

┌──────────┬─────────┬───────┬────────┬──────────┬──────────┐
│ 规格      │ 孔距PCD │ 偏距ET│ 中心孔CB│ 表面处理  │ 生产代码  │
├──────────┼─────────┼───────┼────────┼──────────┼──────────┤
│ 15×7      │ 4×100   │ +35   │ 73.1   │ 白色全涂装│ 1081X157001W │
│ 15×7      │ 4×100   │ +35   │ 73.1   │ 枪灰全涂装│ 1081X157002W │
└──────────┴─────────┴───────┴────────┴──────────┴──────────┘
```

**✓ 必须做的**：

| 项 | 要求 |
|---|---|
| **逐 variant 列** | 不合并 —— 客户要买的是具体那个组合 |
| **生产代码可见** | 客户下单时引用，减少沟通成本 |
| **移动端** | 表格转**卡片**，不横向滚动（竞品在 768 有横向溢出，别重蹈） |
| **`Product` 结构化数据** | SEO |
| **缺失字段留空** | **不填「待确认」以外的任何占位词** |

**⚠️ 四条纪律（安全 + 诚信）**：

1. **只显示该型号实际有的 variant** —— 不用系列通用值顶替（DEC-004）
2. **`process` 未标注的不推测** —— 宁可不显示这一段
3. **不做「适配车型」声称** —— `suitableVehicles` 全空，
   除非该型号 `styleName` 提到某车系，则标注为**「目录标注参考」**
4. **单位写清楚** —— `ET +35`（不是 `35`）、`CB 73.1mm`

**★ 这个规格表是竞品完全没有的。它就是我们相对竞品的核心竞争力。**

**照学竞品的结构**：

  [色卡] [色卡] [色卡] …

**我们的数据**：`finishes` 覆盖率 **100%**，实测 **679 个去重值**（高亮黑 195 / 黑色车面 137 / 哑黑全涂 60…）。

**⚠️ 679 个不能直接列成列表**，须先按「单色 283 / 车面 217 / 全涂装 152 / 压盘双色 27」分 4 组 —— 见 `wheel-catalog-page.md` §3.4。

|---|---|
| **全涂装** | 白色全涂装 / 枪灰全涂装 / 哑黑全涂 / 亮黑全涂… |

### ⑦ 询盘区（改进竞品）

**竞品的做法**：

```
Diameter [输入框]  Width [输入框]  Offset [输入框，可选]  Notes [输入框]
Finish: Satin Black（可从 10 个里选）
Email / WhatsApp
Request Quote
```

**问题**：客户要**自己知道**自己车的规格。而他多半不知道。

**我们的做法**：

```
① 已选：[15×7 · 4×100 · ET+35 · 白色全涂装]   ← 从规格表点选，自动带入
② 数量 [____]
③ 你的车型 / 备注 [____]                     ← 客户只需要填这个
④ 联系方式
⑤ [请求报价]
```

**✓ 核心改进**：**规格从「客户填」变成「从数据选」。**

**⚠️ 但必须保留「自由填写」出口** —— 因为：
- 客户可能要找**我们目录里没有**的规格
- 491 个单图型号可能数据不全

**→ 表单要有「以上都不是，我要定制」的路径。**

**✓ 询盘必须携带上下文**：`model` + `productionCode` + 来源页，销售一眼知道要什么。

### ⑧ 相关型号

**竞品**：`Related Wheel Designs`，3 个同类别产品卡（图 + 型号 + 一句话）。

**我们的规则**（按优先级）：

1. **同 `styleName`**（若有）—— 同设计系列
2. **同尺寸 + 同 PCD** —— 真正可互换的
3. **同 `process`** —— 同工艺

**✓ 显示 3–4 个**，卡片含：图 + 型号 + 规格摘要（尺寸/PCD）。
**✓ 复用 `product-card.tsx`**（已有组件，`hasRender` 兜底）。

---

### ⑨ 数据说明（竞品没有，我们必须有）

**⚠️ 这一段是我们的诚信底线，也是竞品完全没有的。**

页面底部固定一段：

> **数据说明**
> 本页规格来自生产目录记录，已标注的尺寸 / 孔距 / 偏距 / 中心孔为该配置的实际值。
> 未标注项不代表不支持，仅表示目录中暂无记录。
> 装车前请以最终工程确认为准。

**为什么必须有**：
1. 我们是 B2B，客户会拿这些数字去下单 —— 说清来源是专业，不是示弱
2. 与竞品的「什么规格都不给，让客户自己填」形成对照 —— **我们更透明**
3. 满足 DEC-004（未确认不发布）的形式要求
