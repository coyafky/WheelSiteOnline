# 移动端页面友好度修复计划

- **状态**：completed，2026-10-16 已完成实施与验收
- **创建日期**：2026-10-16
- **来源**：[移动端页面友好度 QA 报告](../../outputs/reports/mobile-page-friendliness-qa-2026-10-16.md)
- **目标**：修复手机端真实内容裁切，降低轮毂目录单页浏览负担，并把移动筛选交互补齐到页面规格要求；保持无 JS GET 筛选、分页、内容接缝和发布门槛不退化。
- **范围**：自密封轮胎移动媒体模块、轮毂目录/旋压目录移动密度、轮毂移动筛选抽屉、空查询参数清理、对应单测/E2E/移动视觉验收。
- **不在范围**：真实素材替换、WordPress 内容迁移、正式发布、DNS、真实邮件、移动端新品牌视觉、改变公开分页数量。

## 1. 当前基线与问题排序

| 优先级 | 问题 | 当前证据 | 处理结论 |
|---|---|---|---|
| P1 | 自密封轮胎证据模块在 390/360px 被裁切 | `Normal road use` 模块内部实测 686px，`Material development` 实测 560px；右侧文字不可读 | 先修，作为阻断项关闭 |
| P2 | 轮毂目录每页 24 张、手机单列，页面约 19,000–23,000px | `/products/wheels` 与 `/products/wheels/flow-formed` 移动实测 | 保持 24 张/页，改为移动两列并做卡片可读性回归 |
| P2 | 移动筛选是流内 `<details>`，不是规格要求的抽屉 | 无 `role=dialog`、无 `aria-modal`；Escape 不关闭 | 保留无 JS 回退，增加 JS 渐进增强抽屉 |
| P3 | 空筛选提交产生 `?q=` | 移动端直接 Apply 后可复现 | 清理空字符串并补 URL 测试 |

## 2. 实施原则

1. **先修不可读内容，再优化密度和交互**：P1 裁切修复独立可验收，失败时不进入下一步。
2. **展示层继续只消费类型化内容**：不改 WordPress 原始响应，不把移动判断塞进内容契约。
3. **无 JS 仍能筛选**：`GET` 表单、URL 查询、分页和空状态继续可用；JS 只增强打开、关闭、焦点和结果定位。
4. **不以页面级 `scrollWidth` 作为唯一通过条件**：增加元素边界与文本可读性检查，防止 `overflow-hidden` 掩盖裁切。
5. **分页数量与响应式布局分开处理**：PC 与移动端都保持每页 24 个型号；移动端通过两列网格降低单页纵向长度，不引入按 viewport 分叉的 page size、分页 URL 或 SSR/SEO 语义。
6. **筛选计数按当前条件联动**：每个选项显示在其他已选条件下仍可匹配的批准型号数；不满足的选项显示 `0` 并保留可见，未选中的 `0` 项禁用，已选中的值不能因计数变为 0 而失去提交能力。

## 3. 分阶段任务

### 阶段 A：P1 自密封轮胎移动裁切修复

**涉及文件**：

- `src/components/safety-tires/self-sealing-tire-page.tsx`
- 必要时补该组件的局部样式或项目设计 token；不直接改原始媒体数据。

**步骤**：

1. 将 `TyreDefinition` 的宽屏 `aspect-[2.45/1] + min-h-[280px]` 限定在 `lg` 断点，移动端使用容器宽度和适合正文叠加的比例/最小高度。
2. 将 `ProductEvidence` 首张 `aspect-[4/3] + min-h-[420px]` 的宽屏高度约束限定在 `lg`，移动端取消会反推出 560px 宽度的最小高度。
3. 保留图片的 `hasRender`/批准状态兜底、文字叠加层和桌面布局；不通过隐藏文字解决裁切。
4. 在 390×844、360×800 逐段滚动，检查模块内部所有可见元素的 `right <= viewport`，并确认标题、正文完整可读。

**完成条件**：

- 两个视口的自密封轮胎页没有元素宽度超出内容列。
- `Normal road use`、`Material development` 的图片和叠加正文均完整可见。
- 桌面 1440×900 的既有布局不发生明显回归。

### 阶段 B：轮毂目录移动密度与分页策略

**涉及文件**：

- `src/app/products/wheels/page.tsx`
- `src/components/wheels/flow-formed-page.tsx` 或其目录视图接线（仅在确认该入口使用独立 page size 时修改）
- `src/lib/wordpress/` 与目录视图类型（仅在现有 `pageSize` 契约不足时修改）
- `PAGE-SPECS/wheel-catalog.md`
- `PAGE-SPECS/flow-formed-wheels.md`

**已确认方案**：PC 与移动端均为每页 24 张；PC 保持现有网格，移动端改为两列卡片。分页数量继续由服务端统一决定，响应式只改变 CSS 网格，不改变结果集合、分页 URL、SSR、无 JS 行为或 SEO 语义。

**步骤**：

1. 盘点 `pageSize` 的唯一来源，禁止在页面组件中再写第二个分页常量。
2. 保持统一 `pageSize = 24`，确认 `totalPages`、`page` 越界 404、筛选结果计数和 `ItemList.position` 仍正确。
3. 在 360–639px 使用两列卡片网格；以卡片可读性为门槛，验证型号、工艺、尺寸/PCD 摘要、变体数量和 CTA 不发生截断或异常换行。
4. 检查 360px、390px 下卡片最小宽度、列间距、图片比例和触控目标；如内容确实无法容纳，优先调整卡片内部排版，不回退到按设备改变 page size。
5. 保持筛选快照、排序、搜索、分页和浏览器返回的 URL 状态；空结果仍为 200 + noindex，越界页仍为 404。
6. 更新页面规格中的移动网格与验收条款，并以已确认决定为实现依据。
7. 核对 `buildFacets` 的计数口径：选中 17 英寸后，宽度/PCD/工艺的计数必须只统计存在同一条批准变体且满足 17 英寸的型号；再叠加第二个筛选时，其他选项继续按两个条件求交集。

**完成条件**：

- 手机每页仍为 24 张卡，但采用两列网格，页面纵向长度目标约降至当前单列的一半；目录与旋压入口使用同一公开集合规则。
- 360/390px 下两列卡片的型号、规格摘要、变体数量和 CTA 均完整可读，无横向裁切。
- 桌面目录仍能完整浏览、排序和翻页，不出现卡片缺失或错误重复。
- 过滤 `18`、组合 PCD + 直径、空结果、分页第 2 页和清除筛选均保持正确 URL 与结果。
- 选中直径后，宽度、PCD 和工艺显示当前仍可匹配的批准型号数；计数为 0 的未选项可见但禁用，已选项仍可清除并正常提交。

### 阶段 C：移动筛选渐进增强为可访问抽屉

**涉及文件**：

- `src/components/wheels/wheel-catalogue-filters.tsx`
- 必要时新增小型客户端交互组件；不在页面组件中手写 IntersectionObserver 或复制筛选业务规则。
- `e2e/wheel-filter.spec.ts` 或新增 `e2e/mobile-page-friendliness.spec.ts`

**步骤**：

1. 保留当前 `<details>`/GET 表单作为无 JS 基线，确认服务器端直接提交仍可用。
2. JS 可用时，将移动筛选增强为固定定位的抽屉或对话框：提供明确标题、关闭按钮、遮罩、`role="dialog"`、`aria-modal="true"` 和 `aria-labelledby`。
3. 打开时把焦点放入抽屉；Tab 不离开抽屉；Escape、关闭按钮和遮罩关闭；关闭后焦点返回 `Filter wheels` 触发器。
4. 抽屉内部保留预期结果数、分组展开、底部 Apply 和 Clear；Apply 后关闭抽屉、更新 URL 并把焦点/滚动定位到结果摘要。
5. 390/360px 验证 header 不遮挡抽屉控件，底部 Apply 有至少 44px 触控高度，长筛选项可以自然滚动。
6. 打开抽屉后选择直径并点击 Apply，确认其他筛选组的计数更新；再叠加一个宽度或 PCD，确认计数继续按同一批准变体求交集，而不是分别拼接型号集合。

**完成条件**：

- 无 JS：GET 筛选、清除、分页和直接访问 URL 仍可用。
- 有 JS：dialog 语义、焦点锁定、Escape、返回焦点和结果定位全部通过。
- 筛选联动计数：单条件、双条件、0 结果、已选项变为 0 和清除筛选均通过。
- 既有 4 个轮毂筛选 E2E 继续通过，并新增上述交互状态断言。

### 阶段 D：URL 清洁与回归补强

**涉及文件**：

- 生成轮毂筛选查询的表单/查询序列化逻辑
- `e2e/wheel-filter.spec.ts`
- 必要时 `tests/` 中的查询契约测试

**步骤**：

1. 提交前过滤空的 `q`、空数组和默认排序，不产生 `?q=`。
2. 验证筛选、分页、清除筛选、刷新和浏览器返回不会重新引入空参数。
3. 确认 canonical、robots、noindex 空结果和 sitemap 逻辑没有被查询字符串清理改变。

**完成条件**：

- 空筛选提交回到无查询参数的基础目录 URL。
- 非空搜索、筛选和分页参数保持原有顺序与语义。

## 4. 验收矩阵

### 4.1 浏览器与视觉

| 页面 | 视口 | 必验内容 |
|---|---:|---|
| `/products/safety-tires` | 390×844、360×800 | T02/T05 图片、叠加文字、无元素裁切 |
| `/products/wheels` | 390×844、360×800、1440×900 | 24 张/页、移动两列、首屏筛选入口、卡片、分页、结果末尾询盘 |
| `/products/wheels/flow-formed` | 390×844、360×800、1440×900 | 移动两列、过滤、工艺锁定、分页和页面密度 |
| `/products/wheels` | 无 JS | GET 筛选、清除、分页和直接 URL |

### 4.2 自动化门禁

至少运行：

```text
npm test
npm run lint
npm run typecheck
npm run build
PLAYWRIGHT_PRODUCTION=1 PLAYWRIGHT_PORT=<隔离端口> npx playwright test e2e/wheel-filter.spec.ts e2e/mobile-page-friendliness.spec.ts
git diff --check
```

若生产服务器启动受到 `.next` 锁或端口占用影响，先回收本任务启动的服务并重新执行；环境退出码不能当作页面通过/失败。

### 4.3 失败判定

- 任一手机视口出现内容被裁切、文字不可读、抽屉焦点逃逸或筛选后 URL/结果不一致：修复计划不完成。
- 仅页面总高度较长但已符合 24 张/页、两列卡片可扫描、分页可达：记录为设计观察，不阻断技术验收。
- 真实素材、图权或产品发布状态缺失：保持现有 `hasRender`/发布门槛，不用占位图冒充修复完成。

## 6. 回滚边界

- P1 移动裁切修复可独立回滚，不影响 WordPress 数据和产品发布集合。
- 移动两列若导致桌面、卡片可读性或分页回归，可恢复移动单列并回到设计评审；不得只隐藏卡片或删除分页来掩盖问题。
- 抽屉增强失败时可回退到原生 `<details>` GET 形态，但在计划未补齐焦点/Escape 交互前不能宣称移动验收完成。
