## 当前发布判断

**No-Go。** 当前版本可用于本地演示和内容评审，不得开放正式域名、搜索索引或真实销售邮件。

## 2026-10-11 P5 后的下一步顺序

1. **先拿发布事实与授权（COM-002/007/008/009）**：指定法定主体、联系渠道和正式域名；由业务/工程签字首批 10–20 个有图型号及规格、图片权；法务批准五项政策与隐私版本。没有这些输入，不开放索引或真实发信。
2. **并行建隔离预发布（COM-011/020/021/023）**：确定 OpenNext 平台、区域和公司账号；接入支持邮件事件的提供商、定时 Outbox、告警、备份与恢复。以 WordPress/MySQL 落库为客户成功标准，模拟未落库、邮件失败和重试；真实 QQ/销售地址测试须另获授权。
3. **再做可索引内容与技术 SEO（COM-013–017）**：逐页审批英文原创文案、证据与媒体；核对正式域名构建时的 canonical/OG/sitemap/robots；抽查分页、404、撤回、语言前缀和内部链接。未审批翻译继续 `noindex, follow`，不要为了增加页面数上架无图型号。
4. **最后预发布 UAT 和放行（COM-022/023）**：桌面、320/390/768 与真机、无 JavaScript、键盘/axe、Core Web Vitals、询盘四态、恢复和回滚演练；将观察结果与发布清单交给业务、销售、工程、法务和技术签字。DNS、公开索引和真实邮件在书面授权后执行。

本地 Astryx P5 属于界面与交互质量门禁，不替代以上商用审批。首页语言链接和 RSC 预取问题已单独回归；其余页面族的内容链接与可索引翻译仍由 COM-014/015 逐页验收。

- 三份报告中的 P0 全部关闭并保留验证证据；
- `npm run check`、依赖审计、API、关键视口和真实邮件测试通过；
- 公开产品集合严格执行“无图不上架、未确认不上架”；
- 内容模块可替换为 WordPress API 而无需修改组件；
- 第二人完成恢复与回滚演练；
- 业务、销售、工程、法务和技术联合签字；
- 未经管理层明确授权，不执行 DNS 切换、公开索引、正式发信、commit 或 push。
