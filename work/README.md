# 任务生命周期

用任务文件跟踪需要跨轮次、跨上下文或需要独立验收的工作。一个任务只保留一份文件，按以下路径移动：

```text
work/queued/ → work/active/ → work/completed/
```

## 目录

- `queued/`：已确定要做但尚未开工的任务；若等用户决策或业务资料，须在任务开头明确标注阻塞原因。
- `active/`：现在确实在推进、且有明确下一步的任务。用户确认前的选项或等待外部资料的任务不要伪装成正在执行；收到确认/资料后再移到 `active/`。
- `completed/`：已达到验收条件，记录结果、证据链接和未解决问题的任务。

## 创建与维护

- 小而明确的改动可以直接做，不为每个改动建任务文件。
- 创建任务时用中文写目标、范围、验收标准、依赖和风险；按需补充实施记录。
- 任务启动时移动，不复制；完成、取消或被替代时更新状态并移至相应目录。
- 任务完成后，`STATUS.md` 只保留当前项目状态与重要证据链接；详细日志留在完成记录或报告中。
- 已完成记录是项目历史。过时且无复用价值的任务可整理其正本入口；涉及用户决定或验收的证据不直接删除。
