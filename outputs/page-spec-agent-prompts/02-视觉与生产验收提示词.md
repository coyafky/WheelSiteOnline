# 视觉与生产验收提示词

这段可以交给实施 agent 做自检，也可以交给另一个 agent 独立复核。

```text
请对 <目标路由> 做独立验收。不要因为页面能打开就判定完成，也不要修改 Page SPEC 来迁就当前实现。

先读取根 `AGENTS.md`、目标 Page SPEC、相关内容契约和组件。然后完成以下检查：

一、内容对应

- 逐个列出 Page SPEC 视口编号，确认页面存在、顺序一致、每个只回答一个核心问题。
- 检查 H1、H2、主行动、边界说明和媒体是否共同支持该视口的问题。
- 扫描 Page SPEC 禁止发布的数字、承诺、认证、事故统计、虚构型号、竞品品牌和 `PLACEHOLDER`。
- 检查图片只承担它可以证明的内容，不把场景照片当测试结论。

二、数据与 CMS

- 确认组件没有直接读取 WordPress JSON，也没有硬编码主要营销文案。
- 确认所有公开媒体是 `MediaAsset`，批准状态和本地回退存在。
- 确认同页多图使用一次批量请求，不是 N 次串行读取。
- live 模式统计 WordPress 图片 URL；fallback 模式统计本地 WebP，并确认两种模式都返回 200。

三、浏览器

- 依次测试 1440×900、1280×800、390×844、360×800。
- 必须先滚动整页，让 reveal 和 lazy image 加载完成，再保存全页截图。
- 每个尺寸记录：scrollWidth、clientWidth、图片总数、自然宽度为 0 的图片数、console error 数。
- 360 和 390 必须 `scrollWidth === clientWidth`。
- 检查超长 CTA、表格、筛选器、规格值和竖图是否造成移动端溢出或过度裁切。
- 禁用 JavaScript重新加载，确认正文、主标题与 CTA 仍可见。
- 检查键盘焦点可达、互动目标至少 44×44、链接有明确名称。

四、生产构建

- 运行 `npm run lint`、`npm run typecheck`、`npm run build`，最后运行 `npm run check`。
- 用 `.next/standalone/server.js` 启动生产实例，记录路由状态码、首个 HTML 响应时间和媒体来源数量。
- 检查 canonical/OG/sitemap 使用的 `NEXT_PUBLIC_APP_URL`，不要只看页面 200。
- 运行 `git diff --check`。

五、输出

- 若发现问题，直接修复并重跑受影响检查。
- 把截图保存到 `outputs/<page>-review/`。
- 报告必须区分：已通过、未通过、未验证。不要把未执行的检查写成通过。
- 未全部通过时不要把任务移到 `work/completed/`。
```
