# 剩余页面启动提示词

以下每段都要接在 [`00-单页实施主提示词.md`](00-单页实施主提示词.md) 后使用。主提示词负责完整流程，这里只补充该页面的目标与不可越过的边界。

## 建议实施顺序

```text
1. 轮毂目录
2. 轮毂详情模板
3. 旋压轮毂入口
4. 锻造轮毂高端定制
5. 新能源三电铝制品
6. 定制铝制品
7. 统一询盘页与后端闭环
```

前三项共享 `WheelModel/WheelVariant`、发布集合和筛选逻辑，按顺序实施可以避免同一数据层重复返工。询盘放最后，是因为它需要接住前面页面已经稳定的型号、变体、产品线和客户类型上下文。

## 依赖提示

- 如果轮毂目录还没有完成，不要独立实现详情页或旋压入口的第二套公开集合。
- 如果正式询盘数据库仍未落地，可以先完成表单 UI、校验和契约，但必须把“提交成功”保持在可验证的事务边界内，不能把内存写入描述为生产完成。
- Page SPEC 与当前代码冲突时，以 `PROJECT.md`、`STATUS.md`、现行 Page SPEC 和较新的 `DECISIONS.md` 为准；不得使用归档文档覆盖现行范围。
