# 询盘隐私版本与同意文本模板

> **状态：内部模板，待公司/法务确认。**
>
> 本文件不能直接作为对外隐私政策，也不能替代公司的正式法律文本。未填写正式版本号
> 前，WordPress 中的 `privacy` 与 `request-a-quote` 页面保持草稿，前台询盘表单保持
> 不可提交。这是故意的 fail-closed 保护，不是发布故障。

## 一、需要公司确认的字段

| 字段 | 当前模板值 | 正式上线前必须确认 |
| --- | --- | --- |
| 隐私版本号 | `[待确认：privacy-YYYY-MM-DD]` | 唯一、可追溯、与生效日期对应的版本号 |
| 同意文本 | `[待确认：提交询盘即表示同意公司隐私政策及询盘处理说明。]` | 公司法务批准的中文、英文文本及是否需要分别同意营销通信 |
| 隐私链接 | `/support/privacy` | 正式隐私政策页面的稳定 URL |
| 数据用途 | `[待确认]` | 询盘回复、报价、售后或其他用途的准确范围 |
| 保存期限 | `[待确认]` | 保存期限、删除/匿名化规则和负责人 |
| 数据接收方 | `[待确认]` | WordPress、邮件服务商及其他处理者是否需要列明 |
| 跨境/第三方处理 | `[待确认]` | 是否发生、适用地区和必要披露 |
| 联系方式 | `[待确认]` | 隐私请求、撤回同意和删除请求的有效入口 |

## 二、WordPress 编辑方式

1. 在 WordPress 的“页面”中打开页面键为 `privacy` 的草稿。
2. 只在结构化内容字段中填写上表字段；不要把未确认的假设改写成确定承诺。
3. 打开前端预览，检查版本号、同意文本和隐私链接在页面及询盘入口中完全一致。
4. 业务/法务确认后，再把 `privacy` 与 `request-a-quote` 的“编辑发布状态”都改为
   “已批准”，并发布 WordPress 页面。
5. 触发缓存失效后，重新检查询盘载荷、WordPress 询盘记录、邮件审计字段和 sitemap。

## 三、发布门槛

- [ ] 版本号不是模板占位值，且在变更记录中可追溯；
- [ ] 中文、英文同意文本均已批准；
- [ ] 隐私页面正文、链接和表单同意文本一致；
- [ ] `request-a-quote` 与 `privacy` 均为“已发布 + 已批准”；
- [ ] 草稿、撤回、版本不一致时，前台表单仍显示不可用提示且不会写入询盘；
- [ ] 预览、缓存刷新、sitemap 不收录草稿已验收；
- [ ] 已完成一次运营修改、预览、批准、撤回和恢复演练。

## 四、回滚

若政策内容需要撤回，将两个页面的编辑发布状态改为“已撤回”或“草稿”，保存并触发
缓存刷新。前端会保留最后一次有效本地快照，但由于隐私版本无法通过权威校验，询盘
提交会自动关闭；不得通过修改客户端脚本绕过该门槛。
