# 一个月开发任务卡与模型执行方式

日期：2026-10-04。目标上线：2026-11-04，时区为中国标准时间。状态：待执行。负责人简称：业=朋友/业务负责人，开=你或实施开发者，供=供应商工程/资料联系人，审=内容或政策审核者。

首发范围：英文、四产品线、建议 10–20 个核准轮毂、2 篇文章、WordPress 更新、真实询盘邮件、必要政策与运维。一个型号模板复用多个型号，不逐型号开发。首发不含中文前台、图纸在线上传、多产品询价清单、CRM、视频拍摄、海量产品和独立经销商页。

## 1. 周度里程碑

| 时间 | 主线 | 必须看见的成果 | 若未通过 |
|---|---|---|---|
| 10 月 5–11 日 | 业务/素材、代码基线、部署样机、内容契约 | 一页真实产品能从临时 WP 内容读出；预发布写入数据库样例；页面视口确认 | 先解决运行时或资料来源，不开始批量做页面 |
| 10 月 12–18 日 | 产品导入、真实询盘闭环、首页/目录/详情 | 一次询盘能持久化并在授权测试邮箱收到；产品改动能刷新 | 砍数量与装饰功能，不砍落库和权限 |
| 10 月 19–25 日 | 四线能力页、内容审校、SEO与移动端 | 按逐屏规格浏览完整站点；朋友走 B/C 两条路线 | 非必要文章/额外视觉后移，未授权页仍不公开 |
| 10 月 26 日–11 月 1 日 | 故障测试、政策、预发布、培训 | 发布候选版本、恢复与回滚记录、SEO 报告 | 不添加新功能；修发布阻断项 |

| 11 月 4 日 | 经批准上线 | 正式站点可用、询盘实测、监控启动 | 按手册回滚代码，保留新询盘 |

按约 20–23 个有效开发工作日控制范围，需要朋友每工作日及时确认资料和英文。供应商原件、域名/邮箱或政策审核未就绪，会影响上线；这是依赖，不是 AI 多写代码就能解决的问题。

## 2. 逐步任务

每行是一张可独立派发的任务卡。实际开始时复制到 `work/active/`，填入本次允许修改的精确路径及验收日志位置。任务交回证据后才能标记完成。

|---|---|---|---|---|
| T00 业务事实冻结 / 业 | 无 | 核准画册中英文名、B/C 服务范围、四线供货主体、蓝辉复用范围、正式邮箱、目标国家、响应责任人 | 业务确认表 | 每项有值或明确待办和负责人；不把未知内容上线 |
| T01 素材证据登记 / 业+供+开 | T00 可部分并行 | 用素材表挑图；核对 PPT 原件、40 条定位清单；登记授权、页码、型号、证书主体；先挑首发素材 | 审批后的素材/事实台账 | 页面每张图每条规格可回溯；试用水印文件不入生产 |
| T02 工程基线 / 开 | 无 | 记录版本；选择 npm 锁文件为候选基线并验证安装；旧锁文件按决策归档；配置忽略敏感文件；跑三项门禁；制定 Git 初始化/备份步骤 | 基线报告、环境模板 | 安装与门禁可复现；不上传密钥、不擅自提交推送 |

## 3. 必做与延期规则

**不可削减**：主体与来源正确、四线经确认内容、真实存储、邮件可恢复、权限、WordPress 可维护、英文页面可访问、必要政策、域名与 SEO 正确、备份与回滚。

**优先延期**：增加更多型号、更多文章、复杂动效、视频、画廊、贴牌/经销商独立页、中文前台、在线附件、多产品清单。四线之一的事实/授权未确认时如需先上线其余部分，必须由朋友明确接受范围变化，不能静默忽略该产品线。

## 4. DeepSeek 怎么接手

用户指定 Flash 系列作为主力开发模型。2026-10-04 检索的官方模型页显示当前推荐 API 名为 `deepseek-flash`，版本为 V4.1-Flash，旧 `deepseek-v4-flash` 名称仍接受但映射到新版本。因此执行器应把模型名和服务商配置化，使用前核对提供商实际支持的模型，不假定旧名称锁住了旧版本。[官方模型说明](https://api-docs.deepseek.com/quick_start/pricing/)。

开发模型用于读规格、写代码、修复和整理文案草稿；网站正常运行不依赖每次调用模型，也不需要在生产服务器托管大模型。本计划没有调用付费 DeepSeek API。

每轮执行建议：

1. 只领一个可验收任务；先读根规则、当前状态、相关规格与源码。版本相关 API 先读 `node_modules/next/dist/docs/`，不按记忆猜 Next.js 16 的行为。
2. 给模型本任务所需页面/接口/字段，不一次投喂整个仓库和三本 PDF。视觉任务传对应原页、素材编号和位置表；文字提取不能替代看图片。
3. 一轮只完成一个边界明确的结果，如 T14 可再拆“迁移→事务写入→幂等故障验证”。失败先复现原因，再最小修改，不一次重写全站。
4. 类型/数据结构与生产依赖变更由人复核；安全、迁移、幂等和发布步骤必须查看实际测试证据。编译成功不证明邮件可靠。
5. 内容模型只整理来源已有内容；数字、资质、工艺、适配与法律承诺由业务/工程/审核者签核。
6. 交回修改文件、验收命令与结果、截图、风险和未决项；更新状态。未经明确授权不提交、推送、发真实邮件、购买服务或发布。
