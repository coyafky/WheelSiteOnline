## 3. PPT 内容怎样变成网页

每条内容走以下记录链：原文件 + 页码 → 原始表达 → 事实归属/适用条件 → 英文网页文案 → 所属页面/视口 → 审批状态。

例如“一个轮毂如何做出来”：H3 左上设计图支持“设计与评估”；H4/F9 支持锻造环节；H3 右侧支持检测。应拆成不同问题的视口，并注明工艺路线适用于什么产品。不能把铸造、旋压、锻造拼成所有轮毂必经的一条生产线。

例如“为什么需要自修复轮胎”：先展示真实需求（扎钉、停驶、维修）；下一屏解释内衬自密封机理；下一屏讲测试条件与边界；最后介绍咨询与售后。L6 的事故比例、绝对安全措辞和没有原报告的性能数字不进入网页文案。

以下发现必须人工处理：

- H2 中文写“175 亩”，英文写“175 acres”，单位不一致。未核准前不发布面积数字，不能让翻译模型选一个。
- F19 英文存在拼接残句；网页英文需要专业审校，不能把 PPT 文本直接粘上去。
- F9 的减重比例是宣传口径，不是每款轮毂的保证；不能自动写到全部详情页。
- F12 可支持电机/电控类别，不能据“三电”这个总称假定已经有电池托盘型号与量产能力。
- 供应商联系人、地址、代言人和客户 Logo 不默认进入峰徊站点。业务员邮件、WhatsApp 等用朋友确认的公司联系方式。

## 4. 图片、视频与原件的目录规则

| 层 | 放置位置 | 管理方式 |
|---|---|---|
| 原始资料 | `3家公司的PPT资料/`、现有 `assets/` | 只读，保留原名与 SHA-256 |
| 核验记录 | `resources/research/2026-10-04-site-plan/` | 页级文本、视觉核对图、对象位置表；不自动公开 |
| 素材候选清单 | 本文件与 CMS 私有媒体字段 | 记录来源、页码、产品绑定、权利状态 |
| 已审批图片派生物 | `public/images/` 或正式媒体存储 | 只从合法原件制作，图片使用 WebP；现有轮毂文件名不重命名 |
| 公开文案 | `src/content/` 契约，最终由 WordPress 提供 | 组件不硬编码营销文字 |
| 私密图纸/证明文件 | 私有对象存储 | 不进公开 CDN；经授权签名访问 |

单个素材至少记录 `asset_id`、原文件/页码、内部资源路径、哈希、权利方、用途许可、允许改编与否、所属产品线/型号、尺寸、替代文本、图片焦点、有效期、审核人。一个图可被多个页面引用，但事实归属只有一份记录。

**视频状态**：本次资料目录未见独立视频文件，不能把静态画册称为工厂视频。建议让供应商补 4 段短视频：设计/CNC、锻造机工作、质量测试、自密封材料演示。每段登记出镜工厂、产品、拍摄日期、授权、字幕与测试条件；默认静态封面、用户点击播放、字幕可读，移动端不强制下载大视频。视频不齐不阻塞首发，采用已批准照片与文字流程。

## 5. 产品资产导入步骤与验收

1. 冻结源文件哈希；核对蓝辉与峰徊之间允许复用的数据范围及实际供应商，不修改只读资产。
2. 分别统计主表、生成表、实体图。当前主表 1349 型号/3485 变体；生成表为 1307 条产品记录；实体 WebP 2757 张。记录粒度不同，不能直接相减认定丢失产品。
3. 生成稳定来源键，按命名规则匹配图片，再人工复核冲突；不以近似字符串把不同型号硬绑。
4. 逐变体保留实际规格组合；未知工艺不放进“锻造”分类。没工程确认的车型关系不导入为适配。
5. 首发选择建议 10–20 个资料完整型号；朋友与供应商审核清单。没有通过的条目继续留在候选区。
6. 导入 WordPress 草稿，运行 dry-run 与实际导入结果比对；重复执行不新增重复产品，不覆盖人工改好的英文或审批状态。
7. 正式发布前逐个查看页面、主图、规格、询盘上下文及 sitemap，输出导入总数、拒绝数、原因和已发布数。

图片存在率、授权通过率、规格审核率分开统计。只有三者同时通过的产品才可公开。所谓“素材齐全”必须能够从网页反查原文件和审批记录。
