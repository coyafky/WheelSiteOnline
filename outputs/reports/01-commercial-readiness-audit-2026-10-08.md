## 1. 执行摘要

当前版本的页面框架、响应式基础、真实轮毂数据接缝和 WordPress 询盘持久化方向已经形成，工程构建也能通过；但真正商用需要同时满足“内容可信、客户能顺利提交、询盘不丢且不被滥用、生产环境可回滚、法律与联系信息有效”五个条件。当前至少有 **12 个 P0 发布阻断项**。

最需要管理层理解的不是“页面还差一点”，而是以下差距：

1. sitemap 中有 11 个 URL 会直接渲染 `PLACEHOLDER`，另有 5 个法律页面渲染 `[Assumed — confirm]`；它们当前均可索引。
2. 联系邮箱、电话、地址、正式域名仍是占位值，页面却已经把它们当真实联系渠道显示。
3. 询盘页仍是轮毂专用长表单，不能正确承接四条产品线和个人客户；页面宣称“三个字段、一分钟”，实际有八个必填项。
4. 浏览器没有生成幂等键，重试可能创建重复询盘；同时客户端只把 HTTP 201 当成功，无法正确处理设计中的幂等重放 200。
5. 没有限流、蜜罐、时间陷阱、人机验证或 Origin 防护，公开 API 可以被批量灌入垃圾询盘并触发邮件。
6. 隐私同意不是用户勾选，而是服务端自动写入时间和 `unversioned` 版本，不能证明用户实际同意了什么。
7. `npm audit --omit=dev` 报告 14 个漏洞，其中 2 个 critical、10 个 high；直接依赖 Next.js 16.3.5 在受影响范围内。
8. OpenNext、目标平台、正式 WordPress/MySQL、备份、监控、告警、域名和 TLS 均未落地。
9. 138 个轮毂型号是为了验收筛选而批量批准，不是 10–20 个经业务签字的首发集合；部分主图只有百像素级源尺寸。
10. WordPress 目前主要接管媒体和询盘；页面文案及轮毂发布快照仍在代码仓库，编辑改文案/上新/撤回后仍需要同步与重新构建。

### 2.2 WordPress 补充复验结论与边界

- Docker 启动后已重新执行 [`scripts/verify-inquiry-backend.py`](../../scripts/verify-inquiry-backend.py)，最终 **66/66 通过**。事务探针分别在 `wp_insert_post` 和 outbox 写入处制造 COMMIT 前失败，键行、CPT、meta 与 outbox 均完整回滚。
- 同一幂等键首交返回 201、重放返回 200，并保持一条 CPT、一条键记录、一条 outbox；错误输入返回 422 且数据库计数不变。
- worker 实测了 5 分钟 WP-Cron 注册、到期筛选、有效租约互斥、过期租约回收、失败后释放租约、1/5/15/60 分钟退避、第五次放弃和放弃后不再领取。
- worker 失败重试探针只在该 PHP 进程内清空 SMTP 授权码，没有改动容器长期配置，也没有为五次失败测试发送邮件。
- 两次完整验收共生成 8 条 `Verify Probe` 测试通知，SMTP 均返回 `accepted`；测试 CPT、键记录和 outbox 已清零。`accepted` 仍不能证明最终 `delivered`，因此提供商事件回调问题保持未关闭。

### 2.3 本轮仍没有声称通过的项目

- 没有目标 OpenNext 平台和预发布环境，因此没有验证 Workers 运行时、缓存、定时任务、回滚、备份恢复、TLS 或真实域名 SEO。
- 没有邮件提供商签名事件入口，因此没有验证 delivered、bounced、乱序事件、销售回复和退信告警。
- 没有真实移动网络与真实用户数据，因此不宣称 Core Web Vitals 或转化率达标。
