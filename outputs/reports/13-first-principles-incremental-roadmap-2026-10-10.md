# 基于第一性原理的下一阶段增量路线图

## 一、先确定网站真正要完成的任务

海外采购商或经销商第一次访问网站，最终只需要完成三个判断：

1. **我是否找到了匹配的产品或能力？**
2. **这个供应方是否可信、可沟通、能承接我的需求？**
3. **我现在应该提交什么信息，下一步会发生什么？**

因此网站的价值链不是“展示更多区块”，而是：

```text
定位需求 → 找到产品/能力 → 验证证据边界 → 选择规格 → 提交询盘 → 获得可预期回复
```

任何 UI、内容或图片增量，都应该回答其中一个问题；不能只增加装饰、动画或区块数量。

## 二、对现有 UI 审计的证据化判断

### 已确认的事实

- 当前品牌色、字体、深色/浅色章节节奏和轮毂目录白底陈列已经形成稳定识别度，不需要换色或
  全站重做。
- Header、Footer、轮毂筛选、两步询盘、语言下拉和基础 WCAG/键盘/200% 缩放已经有自动化
  回归；26/26 浏览器测试通过。
- `FloatingQuote` 已经在询盘页、感谢页、页脚和移动筛选打开时抑制显示，但“是否遮挡产品图”
  仍需要逐视口截图确认，不能仅凭代码断言解决。
- Hero 图片使用首图 eager/high priority、深色背景和渐变覆盖；图片缺失时页面仍有背景色，
  但真实网络下的 LCP、主图完成感和移动裁切仍需要单独测量。

### 高概率的体验问题

这些问题来自页面结构和用户任务，不是颜色错误：

- 首页首屏更强调“我们有什么能力”，还没有足够直接地回答“我该从哪里开始”；
- eyebrow、编号、大写和边框规则密度较高，信息容易像展板而不是采购入口；
- 移动端长页面可能让用户在到达询盘前滚动过多；这是需要截图和滚动深度验证的假设，不能
  直接把主观评分当成缺陷；
- 询价浮动入口、目录筛选和首屏 CTA 可能同时争夺注意力，需要每个页面只保留一个主行动；
- 语言框架已经支持四种路径，但中文、西班牙语、泰语正文仍处于 noindex 迁移阶段，不能把
  chrome 翻译误认为全站翻译完成。

## 三、下一阶段的优先级

### P0：让用户更快找到正确入口

**目标**：第一次访问者在首屏选择“我有轮毂型号 / 我有图纸或样件 / 我想了解产品线”，而
不是先阅读完整公司介绍。

**最小改动**：

- 保留 Hero 视觉和品牌标题；
- 将主要 CTA 收敛为一个“选择需求入口”模块；
- 三个入口分别带上既有 `product_line`、`intent`、`input_type` 上下文；
- 询盘页显示“你从哪里开始”的确认条；
- 不删除产品线和能力内容，只把它们从首屏决策前移到决策之后。

**验收**：桌面/移动首屏能看到三个入口；点击后 URL 上下文正确；询盘后台能看到来源；无重复
主 CTA。

### P0：修复移动端行动入口遮挡风险

**目标**：浮动询价按钮永远不遮住主图、规格、筛选或表单控件。

**最小改动**：

- 为目录产品图、筛选抽屉、页脚和安全区建立截图断言；
- 浮动按钮进入主图或页脚区域时自动弱化或隐藏；
- 在 `/products/wheels` 移动筛选打开时保持隐藏；
- 在 `/request-a-quote`、`/thank-you` 保持隐藏；
- 保留键盘可达性，隐藏时从 Tab 顺序移除。

**验收**：360/390/768/1440 四个视口无遮挡、无横向溢出，询价入口仍可发现。

### P1：降低信息密度，而不是重新设计品牌

**目标**：保留工业专业感，同时提高阅读舒适度。

**改动顺序**：

1. Barlow Condensed 只保留给 H1/H2、少量编号和品牌标签；
2. 普通按钮、表单标签和正文使用 Inter 的普通句式；
3. 每个区块最多一个 eyebrow 和一个主行动；
4. 编号只用于真正的流程步骤，不用于普通内容卡片；
5. 移动端减少重复说明，详情内容改为“核心信息 + 可展开证据”。

**验收**：对比截图中 H1、H2、表单标签和 CTA 层级清晰；不新增裸色值、不破坏内容接缝。

### P1：让 Hero 图片失败时仍然像完成页面

**目标**：网络慢、媒体暂时失败或图片延迟时，用户不会看到“页面没加载完”。

**改动顺序**：

- 保留稳定的深色渐变/工业纹理作为完整背景；
- 图片加载前后不改变 Hero 高度和文本位置；
- 对首图记录加载时间、解码失败和 LCP；
- 移动端使用更适合文字可读性的焦点位置；
- 不把生成图当成真实产品证据。

**验收**：禁用图片、慢速网络和正常网络三种场景下 H1/CTA 均可用，CLS 不跳动。

### P1：提升轮毂目录的选择效率

**目标**：采购商能快速从“型号、PCD、尺寸、工艺”进入可询价配置。

- 保留当前真实 variant 筛选和服务端复核；
- 产品卡只展示决定下一步的字段：型号、主图、工艺、关键尺寸、配置数量；
- 继续支持多款加入询价清单；
- 图片缺失、图权未确认或规格不完整的型号不显示；
- 对筛选结果、空结果、清除筛选和移动抽屉做截图回归。

### P1：把多语言从“框架完成”推进到“正文可审阅”

- WordPress 运营逐页填充中文、西班牙语、泰语正文、SEO 和媒体 alt；
- 前台预览后再批准；
- 只有批准语言才加入 `INDEXABLE_LOCALES`、hreflang 和 sitemap；
- 不复制英文正文伪装成目标语言。

### P2：建立最小可用的体验数据反馈

在不引入复杂分析平台前，先记录匿名事件：

- 首页三个入口点击率；
- 目录筛选使用率和空结果率；
- 加入询价清单到提交的转化率；
- 两步表单各步骤退出率；
- 移动端浮动 CTA 点击率。

这些数据用于判断下一步应该优化文案、筛选、产品数据还是表单，不用凭审美争论。

## 四、暂时不要做的事情

- 不换整套颜色；
- 不加入紫色 AI 光效或聊天机器人作为首要入口；
- 不一次性重写所有页面；
- 不继续增加动画、编号、边框和 CTA 数量；
- 不用生成图片冒充缺失产品；
- 不在真实翻译、产品签字和图权完成前开放多语言 SEO。

## 五、推荐执行顺序

```text
P0 需求入口 → P0 移动遮挡 → P1 字体/密度 → P1 Hero 韧性
→ P1 目录选择效率 → P1 多语言正文 → P2 数据反馈
```

每个切片都要通过现有询盘、WordPress、内容类型和 sitemap 回归；不做跨页面一次性大重构。

## 六、2026-10-10 执行结果

本轮按上述顺序完成了前三个可独立验收的切片：

1. **首页需求入口**：Hero 首屏新增三个采购起点，分别携带真实 `product_line`、`intent`、
   `input_type`、`from` 参数；进入询盘页后来源条可观测并随提交上下文进入既有保存链路。
2. **移动端行动入口安全区**：390×844 视口下浮动询价入口距底部保留 78px 加系统安全区，
   询盘页/感谢页/页脚/筛选抽屉的隐藏逻辑和 Tab 行为保持不变。
3. **Hero 媒体韧性**：批准图片触发加载错误时切换同尺寸工业网格；标题、CTA 和 Hero 高度
   不依赖图片成功，不生成或修改任何产品事实。
4. **字体层级第一刀**：普通首页 CTA 与浮动询价入口改用 Inter 正文字体、普通句式和正常字距；
   Hero 需求入口在 1280×720 与 390×844 首屏可见。

自动化证据：`npm test` 31/31、`npm run lint`、`npm run typecheck`、`npm run build` 191 页、
`CI=1 npx playwright test --project=chromium` 30/30、`git diff --check`。截图位于
`outputs/reports/ui-evidence-2026-10-10/`：`home-1280x720-after.png`、
`home-mobile-after.png`、`home-desktop-after.png`、`wheels-mobile.png`。

仍未宣称完成的工作：表单/普通区块字体的逐页收敛、轮毂目录选择效率的新增观测、已批准语言正文
迁移和匿名行为数据反馈。这些继续按 `work/active/` 与 `work/queued/` 的生命周期推进。
