# Pre-Run CLI 视觉对齐与 AI 味诊断

日期：2026-10-13  
方式：Playwright CLI，本地 `WP_MODE=mock` 开发实例，端口 `3300`  ️
范围：首页、产品总览、轮毂目录、制造与质量、安全轮胎、项目询盘。  
视口：1440×900、1280×800、390×844、360×800。  
截图目录：`outputs/reports/pre-run-visual-diagnosis-2026-10-13/`

## 一、结论

当前最严重的视觉问题不是栅格错位，而是安全轮胎页 T03「材料闭合」模块使用了带有伪文字/乱码的图片资产。图片中的文字形状已经被烘焙进 WebP，桌面端露出大段不可读字符，移动端被裁成只剩尾部字母；这会直接破坏工程可信度，应视为上线阻断项。

其他主要问题是：中文路由的页面主体仍大量回退到英文；询盘页桌面端表单过度左置、右侧形成大面积空白；能力页、产品页和安全轮胎页重复使用编号卡片、三列/四列图片卡和统一胶囊按钮，整体呈现明显的模板化/AI 生成感；移动端长页面过长，信息密度和重复卡片造成阅读疲劳。

## 二、问题清单

### P0｜安全轮胎 T03 图片含伪文字与断裂裁切

页面：`/zh/products/safety-tires`  
模块：`T03 / THE MATERIAL CLOSES AROUND THE PUNCTURE CHANNEL`  
证据截图：

- `safety-tires-1440-material-section.png`
- `safety-tires-390-material-section.png`
- `safety-tires-360-preload.png`

原始资产：

- `public/images/safety-tires/mechanism-entry.webp`
- `public/images/safety-tires/mechanism-surround.webp`
- `public/images/safety-tires/mechanism-close.webp`

现象：

- 第一张图底部出现 `10AKF "s...` 一类不可读伪文字。
- 第二张图出现被截断的 `...lf-sealing" memory coa...`。
- 第三张图在移动端只剩 `ting` 等尾部字符。
- 1440 宽度下三张图各渲染约 375×190；360 宽度下各约 318×161。问题随断点保留，说明不是截图缩放误差。

判断：这是图片内容本身的生成质量问题，不是 CSS 文本溢出。图片中混入了 AI 伪文字，且与页面下方真实 HTML 标题重复竞争注意力。工程/制造类页面不能保留这类资产。

建议：立即替换为无文字的剖面示意图、真实测试照片或 SVG/HTML 标注图。替换前不要通过缩小图片或增加 `overflow` 掩盖问题。

### P1｜中文路由的语言层与视觉层不一致

页面：`/zh/products/safety-tires` 以及其他中文页面。  
证据：Playwright 控制台出现：

`[i18n] fallback locale=zh scope=safety-tires reason=no-approved-translation`

截图中页头、导航和页脚为中文，主体 Hero、卡片标题和说明仍为英文。即使排版几何是对齐的，用户仍会感知为未完成的拼接页面；这也是明显的 AI/模板拼装感来源。

建议：中文页面只在有批准翻译时展示中文主体；没有批准翻译时应明确显示语言状态，或暂时不将该语言页面作为正式入口，而不是中英文混排。

### P1｜询盘页桌面端内容过度左置

页面：`/zh/request-a-quote`  
证据截图：`request-a-quote-1440-preload.png`

Playwright 实测：

| 元素 | x | 宽度 | 右边界 |
|---|---:|---:|---:|
| 内容容器起点 | 130 | 1180 | 1310 |
| 询盘表单 | 130 | 760 | 890 |

表单右侧在主内容容器内留下约 420px 的连续空白，且表单区域高度约 973px。视觉上像是右栏内容被删除或模块尚未完成，而不是有意的单列表单。390px 移动端的容器为 x=20、宽=350，无横向溢出，因此问题主要发生在桌面构图。

建议：二选一：将表单列居中并收窄整体内容区，或在右侧补充“需要准备什么/我们如何处理/响应边界”等与填写动作直接相关的说明。不要只把表单拉宽到填满空白。

### P1｜跨页面组件模式重复，AI 模板感明显

涉及页面：能力页、产品总览、安全轮胎页、轮毂目录。  
证据截图：

- `capabilities-1440-preload.png`
- `products-1440.png`
- `safety-tires-1440-preload.png`
- `wheels-1440-preload.png`

重复模式包括：

- 每个章节都使用小号橙色眉题 + 全大写窄体标题。
- 内容主要被切成等宽边框卡片，再配统一的圆形编号、箭头/勾号和胶囊按钮。
- 能力页连续使用三列图片卡；安全轮胎页连续使用三卡/双卡；产品页和目录页继续使用同一类卡片节奏。
- 颜色、边框和间距虽一致，但模块之间缺少“主图、流程、证据、规格、行动”的层级差异。

判断：这是设计系统一致性过度，不是单个像素错误。页面会显得像同一提示词批量生成的长页面，尤其在安全轮胎页最明显。

建议：保留令牌和字体，但为不同信息任务更换版式：流程用时间线/步骤轨迹，证据用对照表或标注图，能力用一张主视觉配证据列表，产品用更强的产品图与规格层级，CTA 只在真正的决策节点出现。

### P2｜移动端长页面重复堆叠，阅读节奏过长

实测完整页面高度：

| 页面 | 390px | 360px |
|---|---:|---:|
| 制造与质量 | 约 11333px | 未单独记录 |
| 安全轮胎 | 约 14526px | 约 14734px |
| 轮毂目录 | 约 19513px | 未单独记录 |

这些页面没有横向溢出，但在移动端把大量重复卡片逐一纵向展开，导致用户在到达关键询盘动作前需要连续滚动很长距离。安全轮胎页尤其在 T01–T05 之间重复出现相似图文卡。

建议：移动端为章节增加可折叠摘要、页内目录或“先看结论”入口；不是简单压缩字号。工程证据可保留，但应按用户任务分层，而不是全部平铺。

## 三、已排除的误报

- 轮毂目录首次快速跳到页面底部时出现的未加载图片不是实际破图。按页面逐段滚动预热后，1440 和 390 均为 25/25 图片加载、0 个 broken image。
- 已测页面的 `scrollWidth` 与视口宽度一致：安全轮胎 1440/390/360、轮毂目录 1440/390 均未发现页面级横向溢出。
- 能力页的桌面网格、产品总览的四列产品卡和移动端纵向堆叠，几何上总体对齐；主要问题是重复模板感和页面长度，不应误写成栅格错位。

## 四、建议处理顺序

1. P0：替换安全轮胎 T03 三张机制图，并重新拍 1440/390/360 局部截图。
2. P1：确定中文内容的批准策略，清理中文路由主体的英文回退。
3. P1：重排询盘页桌面端右侧空白，形成真正的双栏信息关系或居中单列。
4. P1：为流程、证据、产品和能力模块建立不同的版式语法，减少连续编号卡片。
5. P2：移动端增加章节导航/摘要/折叠，降低长页面的重复滚动成本。
