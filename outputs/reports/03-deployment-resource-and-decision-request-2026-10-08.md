用途：供上级审批资源、确认业务事实、指定责任人和授权上线
建议结论：**现阶段先批准“预发布建设与资料补齐”，不要直接批准公开上线。**

开发侧已经完成两步四线询盘、隐私技术门槛、浏览器幂等、应用层反滥用、WordPress
最小权限、未批准页面 noindex/sitemap 退出、英文单语、安全响应头、永久重定向、CI
与契约测试；生产依赖审计为 0 漏洞，Docker 询盘验收为 69/69。上述事项**不再需要
向上级申请是否修复**。

本次真正需要请示的是开发无权代替公司作出的决定与资源投入：

1. 谁是对外法定主体，以及正式域名、公司邮箱、电话、地址和责任人；
2. 哪些产品允许首发，图片、规格、供货与图权由谁签字；
3. 目标市场、B/C 政策与五份法律文本由谁批准；
4. 采用哪个 OpenNext 平台、区域、公司账号、付款人和月度预算；
5. 生产 WordPress/MySQL、邮件服务、域名 DNS、监控、备份与告警由谁提供和管理；
6. 谁执行预发布 UAT、邮件送达/退信测试、恢复/回滚演练，以及谁最终授权 DNS、
   开放索引和真实发信。

换言之，下一笔管理投入应直接用于“预发布基础设施 + 真实业务/法务资料 + 责任人”，
不应再停留在是否补基础表单或是否修依赖漏洞。

## 1. 需要上级先知道的事实

网站代码已经可以完成 lint、类型检查和生产构建，主要展示页也具备较好的视觉基础；但正式部署不是购买一台服务器即可。当前还缺少法定主体与联系信息、首发产品签字、法律政策、可靠询盘闭环、目标平台、正式 WordPress/MySQL、邮件域名配置、监控备份和上线授权。

本地 WordPress 询盘后端已完成 69/69 项集成复验，事务回滚、幂等、outbox、5 分钟 WP-Cron、租约、退避、最大重试次数与权限矩阵均通过。SMTP 返回 `accepted`，但还没有提供商签名事件回调，不能证明邮件最终 `delivered` 或 `bounced`；生产平台定时任务、告警与恢复也尚未验证。

如果现在直接开放域名和搜索索引，可能出现以下后果：

1. 正式联系人仍未提供，客户缺少经业务确认的直接渠道。
2. 五份政策尚未获法务批准，虽然已禁止索引，但不能作为正式合同与隐私依据。
3. 邮件服务只返回“已接受”而非“已送达”，团队可能误以为销售已经收到。
4. 138 个测试批准型号全部公开，其中部分图片分辨率和商业资料不符合上架标准。
5. 平台边缘限流、定时任务、监控和告警尚未在生产环境验证。
6. 发生数据丢失、误发布或回滚时，目前没有经过第二人演练的恢复路径。

因此，本次请示应分成三类：业务事实确认、账号与预算资源、上线与风险授权。

## 2. 请管理层确认的 12 项决定

| D-03 | 销售邮箱、电话、工作时间和询盘负责人是什么？ | 使用公司域名邮箱；主负责人和备份负责人各一名；明确首次响应时限 | 页面仍只能显示假值，真实询盘无人处理 | 销售负责人 |

| D-05 | 图片、证书、检测报告和商标的使用权由谁确认？ | 建立来源、授权范围、有效期和批准人清单；未确认资源不上线 | 侵权、过期证书或无法举证 | 品牌/质量/法务 |

| D-07 | B 端与 C 端分别承诺什么？ | 明确最低起订量、是否零售、安装责任、运费税费、售后与退换边界 | 表单和页面无法给出真实预期，销售重复解释 | 销售/运营 |
| D-08 | 采用哪个 OpenNext 目标平台和部署区域？ | 先做一套预发布成本与运行验证，再定生产；前端、CMS、数据库和媒体资源应同区域或低延迟互通 | 无法验证运行时、缓存、定时任务、费用和数据跨境 | 管理层/技术负责人 |
| D-09 | 邮件服务商、发件域名和收件流程是什么？ | 使用支持事件回调的事务邮件服务；配置 SPF、DKIM、DMARC；提供授权测试邮箱 | 无法区分已接受、已送达和退信，且邮件容易进垃圾箱 | 信息化/销售/技术 |
| D-10 | 谁能访问 WordPress 与询盘个人信息？ | 建独立销售角色和最小权限；内容编辑不可默认读取询盘；离职当日回收 | 普通编辑或作者可能看到客户姓名、邮箱和采购需求 | 管理层/人事/信息化 |

### 3.2 账号与基础设施

需要由公司主体创建或接管，避免长期绑定个人账号：

1. 域名注册商和 DNS/CDN 账号，至少两名管理员并启用双因素认证。
2. OpenNext 兼容的前端运行平台和预发布、生产两个环境。
3. 正式 WordPress 与 MySQL；预发布和生产数据隔离。
4. 媒体存储与图片分发能力；明确备份是否包含媒体。
5. 支持事件回调的事务邮件服务及公司域名发件地址。
6. 错误追踪、可用性监控、日志、告警和成本告警服务。
7. 密钥管理位置，不通过聊天、代码仓库或公开文档传递密码。
8. 备份存储，至少有一份与生产账号或区域隔离。
9. 用于 Search Console、统计和站点管理的公司账号；非必要统计在隐私同意完成后再启用。

## 4. 预算请示方式

项目记录中的目标是“每月含运维不超过 1,000 元”。这个数字可以作为低流量阶段的基础设施目标，但不应被解释为包含所有一次性成本。

建议把预算拆成三栏审批：

| 预算类别 | 包含内容 | 请示要点 |
|---|---|---|
| 每月运行费 | 前端、WordPress/MySQL、媒体、邮件、监控、备份、域名摊销 | 批准月度上限和超额告警；预发布先用真实流量模型测算 |
| 一次性专业服务 | 法律审核、产品摄影、英文校对、安全测试 | 单独报价，不挤占月度运行费；这些是上线门槛而非云资源 |
| 一次性开发与迁移 | 四线询盘、CMS 接线、OpenNext、CI、监控和恢复演练 | 明确内部工时或外包预算、验收人和截止时间 |

若管理层坚持总预算必须把三类全部包含在 1,000 元/月内，应书面确认缩减范围，例如只做英文、只上 10 个轮毂型号、暂不公开中文和未成熟产品线；不能通过取消备份、安全、隐私或法律审核来压缩成本。

## 6. 分阶段审批建议

### 审批一：立即批准预发布整改

批准范围：

- 收窄并补齐 10–20 个首发轮毂；
- 建设 OpenNext 预发布、正式 WordPress/MySQL、邮件测试和监控；
- 接入邮件 delivered/bounced 事件回调和平台可靠定时任务；
- 提供并批准主体、联系信息、正式隐私/交易政策与首发产品资料；
- 在预发布复验已完成的四线/B-C 询盘、隐私、幂等、反滥用、最小权限与安全头；
- 完成 UI、API、安全、备份恢复和回滚验收。

这一步不包含 DNS 切换、正式发信或公开索引授权。

### 审批二：预发布通过后批准生产准备

前提：三份审计文档中的 P0 全部关闭，法律与业务材料签字，预发布演练通过。此时批准生产账号、正式域名配置、邮件域名 DNS 和上线窗口。

### 审批三：上线窗口内单独授权公开动作

明确授权以下动作及执行人：

1. 变更 DNS；
2. 开放 `robots` 与 sitemap；
3. 启用真实销售邮件通知；
4. 开始对外宣传；
5. 出现何种指标时立即回滚。
