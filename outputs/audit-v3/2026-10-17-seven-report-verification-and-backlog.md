## 四张图的现状核对

1. 图 1、2 的 **Prisma／独立业务 MySQL** 不符合当前架构正本：询盘写入 WordPress CPT、幂等表和 outbox，使用同一 WordPress MySQL；仓库也没有 Prisma 依赖。`AI Agent → 审核 → Headless Bridge` 是可能的运营目标，目前没有受控 Agent 写入 API。
2. 图 1、2 中 Polylang Free、ACF Free 可以作为插件/编辑能力描述，但不能据此推断所有页面、语言和字段都已完成接管。CMS 事件刷新已接线，但可靠事件入库、重试、对账尚未实现。
3. 图 3 是**目标事件处理流程**；当前能确认的是 WordPress 保存时非阻塞 POST 到 Next、Next 按 tag/path 失效。实体 ID+locale+revision 的统一事件账本、签名时间窗、去重与重试、结果记录、失败告警和人工恢复入口尚未闭环。
4. 图 4 是**候选生产部署图**。正式 OpenNext 平台、CDN/WAF、TLS、备份、监控和 Redis 是否需要均未决；当前不能把图当作已部署拓扑。Redis 只有在所选运行时／多实例缓存需求验证后才列入实现。
